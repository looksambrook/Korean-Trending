# 실제 용례에서 밈을 찾는 실행 도구

프로젝트 루트에서 다음 명령을 실행한다. 밈 이름이나 후보 ID를 입력할 필요가 없다.

```powershell
python -X utf8 -B src/find_memes.py --config configs/meme_finder_youtube_v01.json
```

실행 마지막에 `result.json`과 `report.html`의 절대 경로를 출력한다. HTML 파일을 브라우저로 열면 계열별 실제 제목·채널·게시 시각·출처 링크, 문장 변형, 자동으로 정리한 쓰임과 보류 사유를 볼 수 있다. 별도 서버나 YouTube API 키는 필요하지 않다. 기본 수집·발견 경로는 Python 표준 라이브러리만 사용한다.

## 자동으로 실행되는 일

1. 설정의 공개 YouTube 채널 피드를 관찰한다. 현재 설정은 편의 표본 3개 채널이며 밈 이름 목록은 없다.
2. 별도로 일반 주제 검색 `요즘 밈`의 결과와 일부 영상 설명을 읽는다. 이 경로는 밈 소개·검색 추천에 치우칠 수 있으므로 채널 관찰과 구분한다.
3. 제목에서 비교 구문, 반복 발화, 인용, 철자를 변형한 명칭 등의 단서를 찾아 검색할 표현을 자동 선정한다. 한 번만 나온 표현도 검색 대상이 될 수 있다.
4. 관찰 원문에 실제로 있던 표현으로 추가 검색하고, 관련성과 서로 다른 용례를 고려해 상세 확인할 영상을 자동 선택한다.
5. 게시 시각과 원문을 확인한 용례를 계열로 연결한다. 같은 제목의 복제와 대상이 바뀐 문장 변형을 구분하고, 인명·일반 주제 반복만으로 밈으로 확정하지 않는다.
6. 근거에서 얻은 문법적 쓰임·제작자 설명을 구조화하고 HTML·Markdown·JSON 결과를 저장한다. 의미를 확인할 수 없으면 모른다고 표시한다.

이 과정의 후보·검색어·영상 선택에는 실행 중 사람이나 채팅 에이전트가 개입하지 않는다. 추가 검색은 최초 발견과 별도 단계이며, 이름을 입력하지 않았다는 이유만으로 대표성 있는 자동 발견 성능을 주장하지 않는다.

## 결과를 읽는 방법

- `supported_textual_reuse`: 서로 다른 실제 제목의 변형이나 출처의 재사용 단서를 확보한 상태다. 독립 평가자가 확정한 정답이라는 뜻은 아니다.
- `needs_evidence`: 표현은 관찰했으나 같은 밈 계열이라는 근거나 의미가 부족하다.
- `rejected`: 현재 규칙으로 연결하지 않은 자료다. 이를 비밈 정답으로 간주하지 않는다. 놓친 밈이 포함될 수 있다.
- `independent_use_count: null`: 게시 채널 수만으로 독립 창작 여부를 알 수 없으므로 합산하지 않았다.
- `recent_observed_uses`: 설정된 최근 기간에 게시된 용례 수다. 조회수 순위·유행 증가율이 아니다.

그림·음성·동작을 자동 분석하는 기능은 기본 발견기에 없다. 특히 ‘그 효과음’처럼 서로 다른 대상을 지칭할 수 있는 표현은 이름 일치만으로 같은 음원 계열로 연결할 수 없다. 모든 밈을 빈칸 치환형으로 취급하지 않는다.

## 새 표현을 기존 발견 결과와 연결

```powershell
python -X utf8 -B src/meme_identify.py --result "결과폴더/result.json" --text "확인할 표현"
```

실제 발견한 계열의 구문·표현과 비교해 출처를 돌려주거나 `unknown`으로 답한다. 이것은 규칙 기반 검색·식별이며 LLM의 이해 평가나 모델 가중치 학습이 아니다. 연구자가 쓴 예시나 AI가 만든 예시를 넣을 때는 `--input-provenance researcher_authored` 또는 `ai_synthetic`을 지정한다. `--as-of`로 과거 시점을 주면 당시 없던 지식과 연결을 제외한다.

## 선택: 로컬 언어 모델로 근거 읽기

```powershell
python -X utf8 -B src/find_memes.py --local-model "로컬에_저장된_모델_폴더"
```

`meme_local_understanding.py`는 동일 실제 용례를 주는 U0와 동일 용례에 자동 구조화를 더한 U1 입력을 준비하고 로컬 모델에 전달한다. 모델 파일을 자동 다운로드하거나 유료 API를 부르지 않는다. 기본 수집·발견과 달리 이 선택 단계는 `torch`와 `transformers` 및 충분한 메모리가 필요하다. 메모리가 부족하면 모델 가중치를 로드하기 전에 중단하고 준비된 입력과 이유를 저장한다.

모델 응답은 규칙으로 작성한 지식 및 원문 관찰과 별도 파일에 보존한다. U0/U1 실행 여부와 성능 개선 여부는 다르며, 독립 질문·정답 없이 이해 성능을 수치로 주장하지 않는다. 전체 D0/D1 × U0/U1 비교 연구가 완료됐다는 뜻도 아니다.

## 호출 범위와 기록

기본 설정은 공개 GET 최대 23회다. 채널 3회, 일반 검색 1회와 상세 확인 최대 3회, 자동 선정 표현 최대 4개의 검색·상세 확인에 나머지를 사용한다. 유료 API 비용은 0이며 통신·전력 비용은 추정하지 않았다. 채널·검색어·호출 한도는 설정 파일에서 바꿀 수 있다.

각 실행은 `data/meme_finder/<run_id>/`에 새로 저장한다. 원본 피드·검색 HTML·상세 HTML, 자동 선정한 검색어, 출처, 제외·보류, 오류, 코드·설정 해시와 호출 횟수를 남긴다. `logs/research.sqlite3`가 실행 장부다. 실패를 숨기거나 기존 결과를 덮어쓰지 않는다. 차단·동의 화면·호출 제한을 만나면 우회하지 않고 수집 범위가 부족하다고 보고한다.

게시일과 별도로 실제 수집·이용 가능 시각을 보존한다. 검색 카드의 상대 날짜는 정확한 게시 시각으로 변환하지 않고 탐색에만 사용한다. 나중에 만든 계열 연결·해석은 생성 시각 이후에만 사용한다. 원자료의 30일 보존 검토 기한은 이용 허락이나 무기한 보존을 뜻하지 않는다.

이 도구의 운영 결과와 독립 평가 결과는 구분한다. 전체 밈 재현율, 가짜 후보 비율, 계열 연결 정확도, 모델 이해 점수는 독립 정답 자료가 있어야 측정할 수 있으며 현재 수집 성공이나 소프트웨어 테스트 수로 대신하지 않는다.
