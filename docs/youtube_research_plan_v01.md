# YouTube 트렌드·밈 발견과 이해: 조사 결론과 첫 파일럿 설계

확인일: 2026-09-15 (Asia/Seoul). 상태: 공식 문서·논문 조사와 로컬 준비. 실제 YouTube API 수집, 발견 성능 실험, 모델 호출, 독립 사람 평가는 아직 하지 않았다. 최신 연구 방향은 [RESEARCH_HANDOFF](../RESEARCH_HANDOFF.md)를 따르며, YouTube를 먼저 검증한 후 다중 플랫폼으로 확장한다.

## 1. 확인할 수 있는 것과 아직 확인하지 못한 것

YouTube의 공개 제목·설명·댓글과 영상 문맥은 밈 연구의 후보 자료다. 다만 **트렌드 목록**, **반복·변형되는 밈**, **그 밈을 모델이 이해했다는 증거**는 각각 다른 자료와 평가를 요구한다. 이번 조사는 가능한 경로와 검증 설계를 마련한 것이며, 지금 유행하는 한국어 밈을 자동 발견했다는 결과가 아니다.

| 경로 | 연구에서 맡을 역할 | 확인 수준과 한계 |
|---|---|---|
| 사전 고정 채널의 업로드 목록 → 제목·설명 → 공개 댓글 | 이름을 알려 주지 않은 발견 실험의 후보 관찰틀 | API 명세 확인. 실제 프로젝트 접근·분석 용도·보존 조건과 채널 목록은 미확정 |
| 분야별 Charts / mostPopular | 플랫폼이 선정한 인기 콘텐츠를 보조 관찰 | 모든 분야·한국어 밈을 포괄하는 목록이 아님. 현재 순위의 직접 열람은 이 환경에서 미완료 |
| 날짜·지역·언어 조건 검색 | 고정 채널 밖 자료를 찾는 별도 표집틀 | 이름 없는 검색과 알려진 이름 검색을 서로 다른 데이터셋으로 기록. 색인 누락·지연·순위 영향 존재 |
| Google Trends의 YouTube Search | 이미 발견한 표현의 검색 관심도 보조 확인 | 상대적 검색 관심도이며 영상·댓글 사용 빈도나 밈 정답이 아님 |
| 공식 Culture & Trends 보고서 | 서론의 사례, 사후 대조, 후보 채널 탐색 | 편집·선정된 회고 자료. 이름 없는 자동 발견 성능의 정답으로 그대로 사용하지 않음 |
| 허용된 원본 영상·자막, 창작자 제공 자료 | 억양·동작·영상 맥락이 핵심인 밈의 보강 | 제3자 공개 자막의 API 다운로드와 영상 일괄 저장은 일반 공개 접근으로 가정할 수 없음 |

접근 필드·쿼터·정책과 출처는 [접근성 조사](youtube_access_review_v01.md), 방법의 근거와 본문 확인 범위는 [선행연구 검토](youtube_methods_literature_v01.md)에 있다.

공식 Charts 안내는 음악·예고편·게임 등 일부 분야, 국가별 비개인화 목록과 약 30분 갱신을 설명한다. 인기 순위는 여러 신호의 조합이므로 조회수 최대인 영상과도 다를 수 있다. 이 관찰틀 밖의 밈은 놓칠 수 있다. [YouTube Charts 도움말](https://support.google.com/youtube/answer/7239739?hl=en)

Google Trends는 표본 검색을 상대값으로 정규화하며 저빈도 표현의 0은 부재를 증명하지 않는다. YouTube Search에서 확인한 결과만 YouTube 검색 관심도로 표시하고, Google Search의 Trending now를 혼합하지 않는다. 쿼리·지역·기간·검색 유형·추출 시각·시간대를 함께 보관한다. [Trends 데이터 설명](https://support.google.com/trends/answer/4365533?hl=en), [검색어와 주제 구분](https://support.google.com/trends/answer/17309543), [Trending now의 대상](https://support.google.com/trends/answer/3076011?hl=en)

공식 2025 한국 연말 보고서는 특정 노래를 활용한 댄스 커버·코스프레·POV 같은 참여 형태를 소개한다. 이는 매체를 넘는 변형 관계를 조사할 동기이며, 특정 표현의 계열·의미를 이번 연구가 검증한 것은 아니다. 2026-09-10 공식 보고서 소개도 커뮤니티와 참여를 논하지만, 이번에는 소개 페이지를 읽었으며 연결된 전체 보고서·설문 원자료를 확인하지 않았다. [2025 한국 보고서 소개](https://blog.youtube/intl/ko-kr/culture-and-trends/year-on-youtube-2025-korea/), [2026 보고서 소개](https://blog.youtube/culture-and-trends/youtube-culture-trends-modern-mainstream-research/)

## 2. 실행 경로와 실제 접근 점검

우선 검토할 구현은 **사전에 정한 한국어 콘텐츠 채널의 업로드 관찰틀**이다. 채널은 밈 이름을 보고 선택하지 않고 분야·활동성·언어 등 관찰 규칙으로 정한다. 한국 소재 영상 또는 KR에서 볼 수 있는 영상과 한국어 영상은 같지 않으므로 언어 판정을 별도로 기록한다. 편의 표본이라는 한계를 유지하며, 전체 YouTube 재현율을 주장하지 않는다.

1. 연구 목적에 맞는 API 분석·보존 용도와 기본 API 프로젝트 접근을 확인한다.
2. 확정된 채널의 uploads playlist를 찾고, 제한된 기간의 영상 ID를 얻는다.
3. 영상 메타데이터와 시간순 댓글을 정한 페이지 수까지 읽는다. 답글이 일부만 포함되면 별도 호출로 보강하거나 미수집으로 남긴다.
4. 수집 시각·정렬·페이지 한도·실패·댓글 비활성화·수정·삭제를 기록한다. 댓글 수 0과 접근 실패를 구별한다.
5. 원시 근거를 시점별로 고정한 뒤 D0/D1을 같은 자료에서 비교한다.

기술적으로 읽을 수 있다는 것과 분석·보존 용도가 허용된다는 것은 별도 확인 사항이다. 현재 추가 파생 분석 정책에는 심사된 용도에 대한 NLP·태깅 예시가 있지만 이 프로젝트의 승인 사실은 없다. 정책 적용과 데이터 생명주기 검토 전 무기한 댓글 수집을 실행 계획에 넣지 않는다. 창작자가 API 밖에서 원본 자료를 직접 제공하는 경로도 별도로 검토할 수 있으나 제3자 댓글까지 권한이 생긴다고 보지 않는다. [개발자 정책](https://developers.google.com/youtube/terms/developer-policies), [추가 분석·보존 정책](https://developers.google.com/youtube/terms/derived-metrics-policy)

공개 화면 접근 점검 결과: 공식 도움말이 연결한 Charts 두 URL은 웹 텍스트 도구에서 행 목록을 반환하지 않았고, Gaming 페이지는 일반 링크만 반환했다. 브라우저 도구는 `No browser is available`을 반환했다. 서비스가 폐쇄됐다는 뜻이 아니라 **현재 도구로 차트 항목을 관찰하지 못했다**는 기록이다. API 키·OAuth·사용자 계정은 생성하거나 사용하지 않았다. 같은 환경의 같은 시도는 사유 없이 반복하지 않는다.

## 3. 단계별 입출력 명세

| 단계 | 입력 | 출력 | 검사할 조건 |
|---|---|---|---|
| 관찰 | 플랫폼, 고정 채널/검색틀, 기간, 요청·페이지 설정 | Observation와 CollectionRun | 출처·게시·수집·이용 가능 시각, 접근 실패 포함 |
| 후보 탐지 | 시점 T까지 허용된 동일 Observation 집합 | Candidate: 임시 ID, D0/D1, 점수, 근거 ID | 알려진 seed 유무, 비밈·보류, 미관찰 항목 추측 금지 |
| 플랫폼 내부 계열화 | 후보, 실제 변형, 복제 관계·문맥 | PlatformFamily 및 각 소속 edge | 같은 문구의 다른 기능, 다른 문구의 같은 기능, 복제와 변형 구분 |
| 플랫폼 간 연결 | 플랫폼별 계열과 이용 가능 근거 | CrossPlatformLink: 양끝 ID, 근거, linked_at, 신뢰도 | YouTube 파일럿은 빈 연결집합. 다른 플랫폼의 성능으로 확대하지 않음 |
| 지식화 | 계열, 시점 제한 근거·연결 | KnowledgeVersion: 의미·의도·조건·변경/보존 특징 | 근거 ID, 충돌·불확실성, automatic/human_reviewed 구분 |
| 검색·식별·이해 | 격리된 새 질문, 그 시점 지식베이스 | Answer: 예측 계열, 의미·의도·적합성, 근거, 보류 | 질문의 정답 계열로 oracle 검색 금지; U0/U1 원시 근거 동일 |
| 평가 | 독립 정답, 모든 계획 질문과 후보·실패 | 단계 점수, 전체 성공률, 비용·오류표 | 미발견·가짜 후보·연결 실패·API 실패를 분모에서 숨기지 않음 |

### 최소 레코드

- **Observation:** `observation_id`, `platform`, `source_id`, `parent_id`, `source_url`, `text`, `text_field`, `context`, `modality`, `posted_at`, `updated_at`, `collected_at`, `available_at`, `snapshot_id`, `sample_method`, `rank`, `page`, `collection_run_id`, `language_status`, `provenance`, `access_status`, `content_hash`, `repost_group_id`, `independence_status`, `retention_due_at`.
- **Candidate:** `candidate_id`, `method_version`, `observation_ids`, `seed_mode`(no_named_seed/known_name_lookup/seed_expansion), `score_components`, `created_at`, `available_at`, `review_status`.
- **FamilyMembership/Link:** `from_id`, `to_id`, `relation`(same_family/variant/repost/uncertain), `evidence_ids`, `linked_at`, `available_at`, `origin`, `version`, `supersedes`.
- **KnowledgeVersion:** `family_id`, `platform_family_ids`, `version`, `meaning`, `intent`, `usage_conditions`, `preservation_rules`, `editable_parts`, `modality_dependency`, `evidence_ids`, `interpretation_confidence`, `origin`, `created_at`, `available_at`, `human_review_minutes`.
- **Gold/Question:** `question_id`, `gold_family_id`, `task`, `new_expression`, `context`, `answer_key`, `acceptable_interpretations`, `is_meme`, `modality_needed`, `annotator_ids`, `disagreement`, `evaluation_only=true`. 정답 저장소는 관찰·지식 입력과 분리한다.

공개 댓글은 반환된 `textDisplay`를 사용했다면 그렇게 표시하며 원작성자가 제공한 `textOriginal`이라고 부르지 않는다. 개인 작성자의 식별자를 무조건 수집·해시하지 않는다. 확인할 수 없는 독립성은 unknown으로 남기고, 별도 허용·근거 없이 서로 다른 계정 수를 사람 수로 간주하지 않는다. 작성자 ID 없이도 확인 가능한 서로 다른 원콘텐츠·사용 문맥을 보조 근거로 삼되 독립 창작의 증명이라고 확대하지 않는다.

## 4. 시간 제한·보존·중복

평가 시각 T에서 `posted_at`, 현재 내용 버전의 `updated_at`(알려진 경우), `collected_at`, `available_at`이 모두 T 이하여야 한다. 수집 후 생긴 계열 연결의 `linked_at`과 지식의 `available_at`도 T 이하여야 한다. 시간대가 없는 시각과 시점 복원이 불가능한 항목은 격리한다. 알려지지 않은 수정 이력은 과거 원문으로 복원하지 않는다.

생성된 지식은 결과를 받은 시각 이후에 이용 가능하다. 과거 T의 자료를 지금 처리한 분석은 실제 과거 온라인 운영과 구별되는 replay다. 실제 운영 지연을 주장하려면 그 시점의 수집·계산·공개 지연을 모두 포함한 prospective 평가가 필요하다. 첫 파일럿은 명시된 관찰 마감과 질문 평가 시각을 가진 스냅샷 진단으로 시작할 수 있다. 이후 시점 자료로 사람이 정답을 확정하더라도 그 정보는 평가 저장소에만 둔다.

개발 → 검증 → 시험 기간 순서를 고정한다. 신규 계열 보류군에서는 계열과 상위 파생 계열이 개발·시험에 걸치지 않도록 하고, 별도의 기존 계열 미래 사용군에서는 과거 용례를 허용하되 미래 변형·재유행의 정답을 격리한다. 동일 내용의 재게시로 시험 정답을 사실상 복사하는 누출은 두 군 모두에서 막는다. 동일 문구를 한 건으로 합쳐 실제 독립 사용을 지우는 것도 피한다. 원문 그대로의 복제, 새로운 문맥에서의 인용, 구조 변형을 별도로 센다. 최소 공통 단위는 플랫폼별 관찰 문서 수이며 좋아요·조회수를 플랫폼 간 직접 합산하지 않는다.

시점별 재현성과 플랫폼의 삭제·갱신 조건이 충돌할 수 있다. 원문을 로그·프롬프트·임베딩·스냅샷에 무기한 복제하지 않는다. 보존 가능한 설정·해시·삭제 이력과 내용 저장소를 분리하고, 내용이 삭제된 이후에는 `not_reconstructible` 상태를 표시한다. 삭제 의무를 피하려고 백업에 남기지 않으며, 지식·모델 입력 등의 파생 사본도 해당 범위를 확인한다.

## 5. 독립 정답과 평가

관리 가능한 파일럿 관찰틀의 모든 문서를 시스템 후보를 보여 주기 전에 독립 검토한다. 평가자 수는 미정이고 최소 두 명의 독립 주석은 설계 제안이다. 밈 여부, 계열 소속, 변형/복제, 문맥상 의미, 미디어 필요 여부를 기록하고 불일치를 보존한다. 애매한 자료를 삭제해 일치도를 높이지 않는다.

비밈 사례에는 인사·상용구, 상품·광고 복제, 유명 인물/노래 제목만 반복되는 경우, 문자적 표현, 뉴스 인용, 근거가 한 건뿐인 보류 사례를 넣는다. 뉴스·노래라는 이유만으로 자동 음성 판정하지 않고 표현의 인용 관습·기능을 판정한다. 실제 사례와 AI가 작성한 척도 점검 예문을 섞어 성능을 계산하지 않는다.

의미·의도 척도 초안은 각각 0(틀림·근거 없는 해석), 1(핵심 일부만 맞음), 2(문맥과 독립 정답의 허용 해석에 부합)다. 평가자는 방법명을 보지 않고 모든 조건에 같은 원자료를 참고한다. 결합 지표의 질문 성공 기준은 식별·사용 판단에서는 정답 일치, 의미·의도 질문에서는 두 척도 모두 2인 것으로 제안한다. 복수의 타당한 해석과 매체 부족은 주석 지침에 남기고 합의 전 평점을 보존한다. 실제 성공 임계값·주지표·평가자 수는 개발 파일럿에서 지침을 검토한 후 본실험 전에 확정한다.

| 평가 축 | 주요 결과 | 분모·실패 처리 |
|---|---|---|
| 발견 | Precision@K, 고정 관찰틀 내 계열 recall | 정답 전체 계열; 미발견도 포함. K개를 못 내면 제출 수와 coverage를 함께 표시 |
| 내부/간 계열 연결 | pairwise precision/recall/F1, 잘못 합침·나눔 | 후보들만의 연결 점수와 전체 정답 용례 연결 recall을 따로 보고 |
| 이해 | 식별 macro-F1, 의미·의도 사람 평가, 사용 판단 | 모든 고정 질문. 검색 실패·호출 실패·보류도 상태를 남김 |
| 결합 | 올바르게 발견·연결하고 별도 질문도 맞춘 비율 | 정답 전체 계열을 동일 가중. 미발견 계열은 0 |
| 오탐·부담 | 가짜 후보 수, 참양성당 검수 시간, 토큰·호출·지연 | 가짜 후보를 계열 recall 분모에 넣지 말고 별도 비용에 반영 |

계열 g의 결합점수는 `I(올바른 발견·연결) × 그 계열 질문 정확도 평균`; 전체 정답 계열 G에 대해 평균한다. 이 점수와 모델이 내부 지식으로 맞힐 수도 있는 전체 질문 정확도를 함께 보고한다. 발견된 계열에 한정한 이해 점수는 진단용이다. 정답 집합이 부분 주석이면 완전 recall 대신 검토 범위 내 결과와 미검토 비율을 표시한다.

플랫폼이 추가되면 각 플랫폼 점수, 플랫폼을 동일 가중한 평균, 실제 표본 비중 평균, 교차 플랫폼 연결을 분리한다. 같은 계열이 여러 플랫폼에 있으면 통합 분모에서 중복 계열로 세지 않는다. 새로운 플랫폼 일반화 주장은 별도 플랫폼 보류 평가 전에는 하지 않는다. 통계 분석은 계열·관찰 시간의 의존성을 반영하고, 본실험 전 주지표·표본·비교·효과 크기와 구간 추정 방식을 고정한다.

## 6. D0/D1 × U0/U1 파일럿

| 조건 | 발견 | 이해 입력 |
|---|---|---|
| D0U0 | 단순 어구 빈도·증가 | 발견된 원시 용례·문맥 |
| D1U0 | 변형 구조·독립 사용·문맥 | D1이 발견한 원시 용례·문맥 |
| D0U1 | D0와 동일 | D0U0와 동일 용례·문맥 + 자동 구조화 |
| D1U1 | D1와 동일 | D1U0와 동일 용례·문맥 + 자동 구조화 |

D0는 문서 단위 반복 어구와 이전 관찰 구간 대비 변화로 순위화한다. D1은 부분문구/변형 연결과 문맥 유사도, 확인 가능한 독립 사용·복제 상태를 더해 순위화하고 근거 기반 판정을 한다. 구체적인 토큰화·임베딩·가중치·임계값은 개발 자료에서 비교한 뒤 고정한다. 한 시점만 있으면 급증·발견 지연을 검증했다고 하지 않는다. 변형이 없는 인용·대화·억양형도 후보로 허용한다.

공통 입력·시간·후보 검토 한도·질문 집합·기반 모델을 고정한다. D별 검색 결과의 원시 용례 묶음은 U0/U1 사이에서 같게 하고, U1만 자동 구조화 정보를 추가한다. U1 구조화의 모든 claim 및 링크를 만든 원천 근거 ID도 U0 묶음의 ID 집합 안에 있어야 한다. 계열 전체를 요약한 후 일부 용례만 U0에 주지 않는다. 범위 밖 근거가 필요하면 두 조건에 함께 포함하거나 그 claim을 U1에서 제외한다. U1 때문에 근거가 잘리지 않도록 공통 용례 묶음을 미리 고정한다. U1에 구조화 호출 비용이 추가됨을 보고하고 같은 예산 비교는 별도 설정으로 수행한다. 인간이 레코드를 수정한 조건은 주조건에 합치지 않는다.

모든 질문은 어느 D가 찾았는지와 무관하게 실행한다. 발견하지 못한 계열의 질문도 검색 실패 또는 무관한 검색 결과를 포함한 실제 흐름으로 처리한다. 정답 계열을 입력해 검색을 성공시키지 않는다. 지원 없는 기반 모델 진단을 별도로 두고, 사전학습 미노출을 보장하지 않는다. RAG/문맥 제공은 지식베이스·입력을 바꾸는 것이며 가중치 학습이 아니다.

## 7. 코드·프롬프트·비용 준비

[제안 설정](../configs/youtube_pilot_v01.json)은 아직 채널·기간·모델·예산·권한을 확정하지 않은 로컬 산식용이다. [후보 검토](../prompts/youtube_discovery_review_v01.txt), [지식 추출](../prompts/youtube_knowledge_v01.txt), [이해](../prompts/youtube_understanding_v01.txt) 프롬프트 초안을 분리했다. 프롬프트는 실제 모델에서 검증되지 않았다.

`src/youtube_pilot_plan.py`는 이 설정에서 API 호출 수/쿼터 버킷, 네 개 비교조건, 모델 호출·토큰 산식과 준비 미완료 항목을 산출한다. 수집·D0/D1 알고리즘·모델 실행기는 아니다. 네트워크 호출 없이 log에 등록된 오프라인 준비를 수행하며 같은 설정·코드·프롬프트의 반복 준비를 차단한다.

예시 수량은 6채널·최대30영상·3회 관찰·영상당 최상위 댓글20개 및 전체 답글 페이지 상한을 둔 것이다. 관찰틀·쿼터 계획을 설명하는 가정일 뿐 확정 수집량·연구 기간이나 KCI 조건이 아니다. 페이지 크기를 작게 해도 실제 페이지 호출 자체는 과금/쿼터 산정 단위이며, 실패·추가 페이지도 따로 남긴다. 누락 없이 회수되는 자료량은 실행 전 알 수 없다.

현금 비용은 모델 가격·예산이 미정이므로 `null`로 남긴다. 입력 토큰×입력 단가 + 출력 토큰×출력 단가로 모델비를 계산하고 임베딩·OCR/ASR·사람 검수·저장 비용은 별도다. 계획 토큰은 상한을 보증하지 않는 예시 추정이다. 실제 실행에는 토큰 계수와 지출 한도·실패 처리가 추가로 필요하다. API 쿼터 단위를 USD로 환산하지 않는다.

로컬 산식 검증 결과는 [계획 계산 JSON](../data/research/youtube_pilot_estimate_v01.json)에 있다. 현재 예시는 전체 3회 관찰 합계로 검색 6회(별도 버킷), 기타 145 units이며 하루 사용량은 관찰 시각을 정해야 계산할 수 있다. 모델 호출은 가정상 156회, 입력 504,000/출력 84,000 토큰이고 실제 실행은 0회다. 모든 페이지가 가득 차고 매 시점의 항목을 두 명이 1분씩 검토하면 83시간이라는 보수적 작업량이 나온다. 이 가정은 영상 시청·질문 작성·최종 출력 평가 시간을 포함하지 않는다. 따라서 이 수량을 곧바로 모집·실행 규모로 확정하지 않고, 첫 접근 점검 후 실제 신규 항목 수와 검토 속도로 조정한다.

계획 산출 명령은 `python -B src/youtube_pilot_plan.py --config configs/youtube_pilot_v01.json --out data/research/youtube_pilot_estimate_v01.json`이다. 이번에 이미 등록·실행했으므로 그대로 반복하면 중복으로 차단된다. 결과 경로만 바꿔도 우회할 수 없다. 조건 변경은 변경 이유와 새 명세를 기록하고, 동일 조건의 의도적 재시도는 로그 지침의 이전 run ID·사유를 사용한다.

소규모 문헌 검토·JSONL/SQLite 준비에는 현재 로컬 환경을 사용할 수 있다. 장기간 정시 수집이나 대용량 음성·영상 처리의 필요성이 확인되면 서버/스케줄러 사양과 비용을 별도로 제안한다. 현재 서버 구매 근거는 없다.

## 8. 실험 로그와 다음 실행 기준

[로그 사용법](research_log.md)에 따라 실행 전에 입력·설정·코드·프롬프트·시점·모델 버전을 지문화한다. `logs/research.sqlite3`가 기준 장부이고 `logs/research.jsonl`은 내보낸 열람본이다. 완료·실패·진행 중인 동일 지문이 있으면 자동 재실행하지 않는다. 재시도에는 이전 run ID와 구체적인 이유를 남긴다. 브라우저 미연결이나 API 미설정처럼 조건이 그대로인 접근 실패도 반복하지 않는다.

이번 단계의 완료는 접근 경로의 근거 있는 비교, 누락을 포함하는 평가 설계, 로컬 비용·로그 준비를 뜻한다. 실제로 밈을 파악할 수 있다는 판단은 이후 독립 용례·정답·새 질문으로 확인해야 한다. 다음 실행의 준비 미완료 항목은 프로젝트 접근, 분석·보존 용도, 채널/시간 관찰틀, 모델·비용 상한, 독립 주석 가능 범위다. 그중 공개 문헌·로컬 설계는 지금 수행했고 유료 대량 호출·사람 모집은 수행하지 않았다.
