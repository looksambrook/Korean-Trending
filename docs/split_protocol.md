# 계열 단위 분할과 누출 방지 초안 v0.1

작성일: 2026-09-11. 상태: **실행 전 제안**. 현재 소수 자료의 로컬 점검은 개발 파일럿이며, 본실험 시험 집합이 확정되거나 잠금된 상태가 아니다. 분할 비율과 표본 수는 미정이며 KCI의 공식 기준이 아니다.

## 1. 분할 단위

`family_id`는 같은 원형과 핵심 사용 관습을 공유하는 묶음이다. `lineage_group_id`는 직접 파생·확장 관계가 있는 여러 계열을 묶는 상위 그룹이다. 동일 상위 그룹의 모든 계열은 하나의 분할에만 넣는다. 형태가 다르더라도 원형·핵심 대사·연속 대화에서 파생된 관계가 확인되면 함께 묶는다.

단지 ‘복귀’ 같은 기능이 같다는 이유로 하나의 상위 계열로 합치지 않는다. 파생 관계는 출처나 실제 표현 연속성 등 근거로 판단한다. 관계가 불확실하고 가까운 변형이면 보수적으로 함께 묶거나 판단 완료까지 시험 배정을 보류한다. 기준과 결정을 기록한다. 이 과정은 분할을 유리하게 바꾸기 위해 시험 결과를 본 뒤 하지 않는다.

## 2. 단계별 자료 접근

| 자료 | 프롬프트·규칙 개발 | 고정 프롬프트 구조 추출 | 주 생성 입력 | 최종 평가 |
|---|---|---|---|---|
| 개발 계열 지원 용례 | 가능 | 가능 | 가능 | 개발 점검 가능 |
| 개발 상황·출력·평가 | 가능; 사용 이력 기록 | 구조 추출 입력에서는 제외 | 개발 생성에 가능 | 가능 |
| 검증 계열 지원 용례 | 고정 후보 비교에만 사용 | 가능 | 가능 | 검증 가능 |
| 검증 상황·점수 | 사전 정의한 후보 선택에 사용 가능 | 제외 | 검증 생성에 가능 | 가능 |
| 시험 계열 원문·지원 용례 | **불가** | 잠금된 방법의 추론 입력으로 가능 | 모든 B 조건에 동일 제공 | 정체성 평가 때 동일 제공 |
| 시험 평가 상황 | **불가** | **불가** | 고정 방법의 생성 시점에만 가능 | 상황 평가에 제공 |
| 시험 평가용 예문·정답 | **불가** | **불가** | **불가** | 필요 시 평가 관리자만 사용 |
| 시험 출력·점수·평가 코멘트 | **불가** | **불가** | 재작성·재순위화에 사용 불가 | 최종 분석에 사용 |

검증 결과로 규칙을 자유롭게 계속 수정하면 그 집합은 사실상 개발 자료가 된다. 변경 이력에 이를 표시하고 독립 시험 집합을 유지한다. 시험 지원을 제공하는 설정은 ‘개발에 사용하지 않은 계열에 대한 지원 예시 적응’이며, 지원 없는 zero-shot이나 모델이 처음 본 밈이라는 주장이 아니다.

## 3. 분할 실행 순서

1. 수집·검증한 지원 후보를 원 출처 단위로 정리한다. 지원 수와 독립 출처 수를 모두 센다.
2. 원형·파생 관계를 검토하고 `family_id`와 `lineage_group_id`를 부여한다. 범위 설명용 합성 사례는 실제 표본에서 제외한다.
3. 정규화 문자열의 정확 중복, 유사 문구, 같은 게시물·영상의 재게시를 탐지한다. 자동 유사도만으로 계열 동등성을 확정하지 않고 확인 결과를 남긴다.
4. 유형·매체 의존성·출처 품질 분포를 확인하며 상위 그룹 단위로 개발·검증·시험에 배정한다. 비율, seed, 알고리즘, 예외 사유를 기록한다. 작은 파일럿에서 의미 없는 60/20/20 배분을 강제하지 않는다.
5. 시험 계열마다 지원 풀과 평가 상황을 별도 경로에 보관한다. 평가 상황은 지원 문장 단어 몇 개만 바꾼 문장이나 목표 응용문의 역생성으로 작성하지 않는다.
6. 상황끼리의 중복뿐 아니라 지원 문맥과 평가 상황의 근접 재진술도 점검한다. 공유 원본을 발견하면 어느 경로에서 제외·이동했는지 남긴다.
7. 잠금 전에 데이터·스키마·프롬프트·설정·주 분석 계획의 버전과 해시를 저장한다. 평가 상황 작성자와 개발자를 가능한 한 분리한다.
8. 잠금 후 예외는 수정 사유와 영향 범위를 기록한다. 답을 본 뒤 지침을 고쳤다면 해당 집합을 확증 시험으로 계속 보고하지 않는다.

## 4. 코드 및 파일 경계

현재 구조 추출 요청 생성기는 계열의 `family_id`·`canonical_text`와 지원의 `support_id`·`text`·`context`만 모델 입력으로 전달하는 허용 목록을 사용한다. 구조 추출 명령에는 상황 파일 인자가 없다. 출처·검증 메타데이터는 자료 관리·검증에 사용하며 모델 입력에 추가하지 않는다. 계열별 자동 레코드를 먼저 저장하고 해시를 고정한 후 상황을 생성 요청에 결합한다.

B2와 B3는 같은 레코드 해시를 참조하며, 상황마다 별도로 구조를 추출하지 않는다. 사람 검토본은 별도 경로·`record_origin`·실행 이름으로 관리한다. 검색 인덱스에도 시험 정답·평가 예문·평가 결과를 넣지 않는다. 파일 경로 분리와 검증기는 실수 방지 장치이며, 접근통제 또는 사람의 열람 이력 감사를 완전히 대체하지 않는다. 현재 구현은 ID·출처 종류·상위 그룹·동일 출처 그룹·정규화 문자열 완전중복·해시를 검사한다. 의미적 근접 중복, 파생 관계의 진위, `context` 안에 평가 정보가 섞였는지는 자동 판정하지 않는다. 아래 목록 중 이러한 내용은 사람의 자료 감사가 필요한 설계 점검 항목이다.

권장 검증 항목:

- 하나의 `family_id`가 여러 분할에 등장하지 않는다.
- 하나의 `lineage_group_id`가 여러 분할에 등장하지 않는다.
- 지원·상황·레코드의 계열 ID와 분할이 명세와 일치한다.
- 자동 레코드의 `support_ids`와 모든 `evidence_ids`가 해당 계열의 허용 지원 풀에 포함된다.
- 평가 상황·정답·결과가 추출 요청에 직간접적으로 들어 있지 않다.
- 파일럿을 보고 선택·수정한 계열과 상황은 시험 집합에서 제외하거나 개발 사용을 명시한다.
- 잠긴 시험의 해시와 현재 파일이 일치하며 변경이 있다면 이력이 있다.

## 5. 파일럿과 본실험의 연결

첫 소수 사례 파일럿의 목적은 출처 확인, 비슬롯형 표현 지원, B2/B3 정보 일치, 출력 형식, 평가자 부담을 점검하는 것이다. 이때 읽거나 수정에 사용한 사례는 개발 자료다. 파일럿 성능을 보고 계열·상황을 골라 본시험에 그대로 넣지 않는다.

본실험 계열 수·상황 수는 유형 포괄성, 비용, 평가자 확보, 파일럿에서 관찰한 변동성을 바탕으로 사전 결정한다. 소수 계열에서 얻은 점수로 충분한 검정력이 검증되었다고 쓰지 않는다.

## 6. 남는 한계

계열과 상위 그룹 분리는 개발 자료를 통한 중복을 줄이지만, 기반 LLM의 사전학습에서 원형을 보았는지 보장하지 못한다. 원자료 게시일, 수집일, 모델 ID·버전·실행일을 기록하고 이 한계를 명시한다. 검색 후보 집합의 규모·언어 범위·시점도 별도 기록한다. 텍스트만 수집한 결과를 음성·영상 밈 전체의 일반화 성과로 해석하지 않는다.
