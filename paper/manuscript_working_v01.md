# 한국어 유행어의 보존·변경 요소와 사용 맥락 표현이 상황별 응용문 생성에 미치는 영향

작업 초안 v0.1 · 2026-09-11

**집필 상태:** 서론·관련연구·과제 정의와 실행 전 방법 설계를 작성한 문서다. 실제 모델 원응답과 독립 사람 평정으로 검증한 실증 결과는 아직 없다. 아래에서 ‘설계한다’, ‘비교한다’는 표현은 계획된 절차를 뜻한다. 데이터 최종 구성, 모델, 표본 수, 통계 분석과 투고처는 확정 후 다시 작성해야 한다. 연구 결과를 제시하는 완성 원고로 제출할 수 없다.

운영 목표는 **2026년 12월 전 투고**다. 이는 게재 완료 목표나 학술지 접수 마감일을 의미하지 않는다. 사용자는 평가 대상이 주로 20대이기를 희망했으며, API 예산·모델/GPU·주석자/평가자 수·투고처·공개 범위·기관 사람 평가 절차는 미정이다. 후속 응답에서 본인을 제외한 평가자 6명 이상 확보 가능이라는 자기보고를 받았다. 실제 등록·참여 인원과 최종 표본은 아직 확정하지 않았다. 운영 정보는 최종 원고의 연구방법·윤리·자료 공개 진술에 필요한 사항만 남긴다.

## 초록

**미작성: 실험 후.** 현재 연구 목적과 설계만으로 효과의 방향·크기·유의성 또는 사용자 만족 향상을 요약하지 않는다.

## 1. 서론

한국어 유행어를 새로운 상황에 응용하려면 원문의 일부를 알아보게 유지하면서도 발화 목적과 관계, 매체에 맞게 표현을 조정해야 한다. 이 연구는 ‘거제 야호’, ‘감옥에서 누가 돌아왔게’와 같이 형태가 다른 표현을 하나의 빈칸 치환 규칙으로 처리하기보다, 계열마다 관찰되는 보존 요소·변경 가능 요소·사용 맥락을 명시하는 접근을 검토한다. 두 표현은 연구자가 제시한 출발 사례이며, 그 명칭만으로 원형의 진위나 계열 전체의 적용 규칙을 확정하지 않는다.

문화적 인용의 변형 패턴과 원형별 분할은 이미 연구되었다. Catchphrase는 교체 가능한 부분과 문화적 인용 탐지를 다루고, A Template Is All You Meme는 템플릿 지식과 템플릿 단위 분할을 다룬다. 국내에서도 밈 사전 구축과 문형을 이용한 의사소통 지원, 사회문화적 속성에 따른 유형화가 논의되었다. 따라서 유행어를 수집·분류하거나 보존·변경 요소를 기록한다는 사실만으로 새로운 기여를 주장할 수 없다. [Sweed & Shahaf, 2021](https://aclanthology.org/2021.acl-short.1/), [Bates et al., 2025](https://aclanthology.org/2025.naacl-long.525/), [이대규·이찬규, 2023: 초록 확인](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003044747), [홍소람, 2025](https://www.accesson.kr/kosim/assets/pdf/55396/journal-42-1-183.pdf)

이 연구의 중심 질문은 다음과 같다. **동일 LLM이 동일 원문과 지원 용례를 사용할 때, 보존 요소·변경 가능 요소·사용 맥락을 명시적으로 표현하면 상황 적합성과 밈 정체성 보존이 개선되는가?** 원자료만 주는 조건, 자동 추출 정보를 서술형으로 추가하는 조건, 같은 정보를 필드별로 추가하는 조건을 비교하여 정보 추가를 포함한 방법 차이와 특정 표시 방식의 차이를 구분하고자 한다. 이 질문은 효과를 가정한 결론이 아니며, 두 주요 지표 사이의 상충이나 차이가 명확하지 않은 결과도 보고 대상이다.

계획된 연구의 기여 후보는 한국어 다형태 응용 과제를 위한 자료·평가 절차, 동일 자동 정보에 대한 제공 방식 통제, 자동 추출 오류와 생성 실패의 연결 분석이다. 이 조합의 독창성과 유용성은 추가 문헌 대조 및 실험 후 판단한다. 검색·추천을 포함하는 전체 시스템의 목적은 유지하되, 주 생성 실험에서는 계열을 고정하여 검색 성패가 응용문 품질 비교에 섞이지 않도록 한다.

## 2. 관련연구

### 2.1. 변형 패턴, 계열과 의사소통 기능

Catchphrase는 문화적 인용의 원형과 후보 문장을 대상으로 패턴을 추출하고 인용 여부를 판별한다. 검토한 본문은 복수 패턴을 허용하고 정규식 일치만으로 처리되지 않는 인용을 다룬다. Social Meme-ing은 시각 템플릿과 그 안의 언어적 표현을 바탕으로 의미 기능 및 사회적 변이를 분석한다. A Template Is All You Meme는 템플릿·용례 정보를 구축하고 템플릿을 고려한 분할을 제안한다. 이들은 본 연구가 형태, 기능, 계열을 구분하는 근거지만 한국어 상황별 응용문 생성의 성능 근거는 아니다. Social Meme-ing과 A Template의 본문 설명은 아래 열람 기록에 명시한 저자본에 근거하며 최종 게재판 전체와의 동일성은 아직 확인하지 않았다. [Catchphrase](https://aclanthology.org/2021.acl-short.1.pdf), [Social Meme-ing 저자본 v1](https://arxiv.org/html/2311.09130v1), [A Template 저자본 v2](https://arxiv.org/html/2311.06649v2)

홍소람(2025)은 국내 밈 목록을 여러 속성으로 분류하면서 복합양식 사례의 재생산 방식을 하나의 배타적 범주로 정하기 어려워 해당 분류를 중단했다고 보고한다(195쪽). 본 연구는 이 관찰을 모든 밈의 성질로 일반화하지 않으며, 계열 하나에 여러 응용 방식이 가능하도록 자료 형식을 설계하는 근거로 사용한다. 슬롯이 없거나 원문 인용을 유지하는 사례도 허용하고, 계열 수준의 라벨과 개별 용례에서 확인되는 변화는 구분한다. [홍소람, 2025, §3.3](https://www.accesson.kr/kosim/assets/pdf/55396/journal-42-1-183.pdf)

### 2.2. 맥락 이해와 상황별 생성

SLANG은 문맥에 나타난 새로운 표현의 뜻을 설명하는 과제이고, MemeReaCon은 밈·게시글·댓글의 관계와 태도, 의도를 다룬다. 이해·설명 생성과 사용자의 새 상황에 맞는 응용문 작성은 출력 목적이 다르다. 그러나 맥락이나 의도를 모델에 제공한다는 발상 자체는 본 연구만의 방법이 아니다. [Mei et al., 2024](https://aclanthology.org/2024.emnlp-main.698.pdf), [Zhao et al., 2025](https://aclanthology.org/2025.emnlp-main.176.pdf)

Memenify의 공개 초록은 문맥에 따른 템플릿 추천과 LLM 문구 생성을 설명한다. 이 문헌은 석사학위논문이며 본문을 열람하지 못했으므로 사용자 연구의 비교 조건이나 통계를 단정하지 않는다. HUMOR의 검토한 프리프린트는 템플릿 의도와 상황을 이용한 밈 생성 및 선호 학습을 다룬다. 따라서 ‘상황별 밈 생성 시스템’을 구현했다는 점만으로 차별성을 주장하기 어렵다. 본 연구는 추가 학습을 기본 구성에 넣지 않고, 동일 기반 생성 모델에서 원자료와 자동 추출 정보의 제공 조건을 비교하는 질문에 집중한다. [Wei, 2025: 초록만](https://digitalcommons.dartmouth.edu/masters_theses/203/), [Li et al., arXiv v2](https://arxiv.org/html/2512.24555v2)

### 2.3. 국내 구조·유형 연구와 정체성 개념

이대규·이찬규(2023)의 공개 초록은 밈 사전, 온라인 용례 분석, 문형 작업과 관용표현 대응을 설명한다. 국내 밈 데이터와 이해 지원 시스템이라는 문제의식이 직접 겹친다. 현재 KCI 공개 미리보기는 영문 초록 1쪽이므로 본문의 실제 구현·평가 범위를 확인하지 않은 채 차이가 입증되었다고 서술하지 않는다. [이대규·이찬규, 2023](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003044747)

우성미(2026)는 생성형 AI 기반 사례와 사례군을 질적으로 분석하여 재현 방식·현실 반영·정체성 개입의 조합으로 유형을 설명한다(45–56쪽). 여기서 정체성 개입은 특정 인물·캐릭터·이용자의 정체성이 콘텐츠 구성에 반영되는 정도다. 본 연구의 **밈 정체성 보존**은 응용문에서 원 계열을 알아볼 수 있고 그 핵심 특징·함의가 유지되는지를 뜻한다. 이름이 유사하더라도 두 개념을 같은 척도로 취급하지 않으며, 기존 유형화 연구에 비해 생성 품질이 개선되었다는 비교도 수행하지 않는다. [우성미, 2026, §3-2·§4](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003366058)

### 2.4. 프롬프트 표현 방식의 해석 범위

FormatSpread는 의미를 유지한 프롬프트의 서식 차이에도 모델 성능이 민감할 수 있음을 다룬다. 본 연구는 이 논의를 근거로 서술형과 필드형의 비교를 **잠근 두 렌더링 사이의 차이**로 정의한다. 같은 원자 사실을 보존해도 토큰 수·문장 프레이밍·시각적 묶음은 달라질 수 있으므로, 한 필드형 프롬프트가 더 높은 점수를 얻는다고 모든 구조화 프롬프트의 우월성을 결론 내릴 수 없다. [Sclar et al., 저자 camera-ready v2, §1–3.2](https://arxiv.org/html/2310.11324v2)

## 3. 자료와 과제 정의

### 3.1. 분석 단위와 자료 출처

**계열**은 관련된 원형 후보와 재사용 표현의 묶음으로 정의한다. 같은 원본에서 파생된 가까운 계열은 상위 파생 그룹으로 연결한다. **지원 용례**는 해당 계열의 실제 표현과 관찰 문맥을 제공하는 자료이고, **평가 상황**은 새로운 응용문을 요청하기 위해 별도로 작성·검토하는 상황이다. **응용문**은 고정된 계열을 사용하여 평가 상황에 맞추어 생성한 출력이다. 문자열 유사성만으로 계열 관계와 독립성을 확정하지 않는다.

현재 준비 상태는 개발용 **3개 계열과 2개 확대 후보**이며, 이는 최종 분석 표본이 아니다. 출처 검증·독립성·이용 범위·텍스트만으로 평가 가능한지를 검토한 뒤 편입을 결정한다. 준비 중인 자료 버전의 변화와 관계없이 본실험 계열 수, 상황 수, 반복 수는 아직 미정이다. 개발에 사용한 계열을 최종 시험 자료로 재사용하지 않는다.

실제 웹에서 관찰한 텍스트, 연구자가 직접 작성한 자료, AI 합성 자료, 사용자가 제공했으나 검증되지 않은 표현을 각각 표시한다. 웹 관찰은 그 페이지에서 문자를 확인했다는 의미이며 원 작성자가 AI를 사용하지 않았다는 보장은 아니다. 기사에 인용된 발화는 원영상의 직접 관찰과 구별한다. 설명자가 만든 예시, AI의 맥락 요약, 코드 점검용 합성 문장은 자연발생 용례 수에 포함하지 않는다. 같은 문서·영상의 재게시와 인용은 중복군으로 연결하여 관찰 수·문서 수·독립 사용 수를 구분한다.

### 3.2. 보존·변경·맥락 표현과 주석

표현 레코드는 형태, 의사소통 기능, 보존 조건, 변경 가능 요소, 응용 방식, 사용 맥락, 매체 의존성, 불확실성으로 구성한다. 각 항목은 값과 근거 지원 ID, 확실성 표시를 함께 저장한다. 보존 조건은 어구·어순·리듬·질문 형식·대화 순서·핵심 함의를 포함할 수 있지만, 관찰하지 않은 요소를 계열 전체의 필수 규칙으로 단정하지 않는다.

변경 가능 요소는 빈 목록일 수 있다. 개별 용례에서 확인한 치환 하나가 임의의 단어를 모두 허용한다는 뜻은 아니며, 조사·어미 조정과 말투 적용, 그대로 인용, 대화 재구성을 별도 응용 방식으로 기술할 수 있다. 자동 추출기가 부여한 ‘근거 있음’ 표시는 모델의 판단이며 의미적 타당성을 보장하지 않는다.

사람 주석은 자동 추출의 근거성·누락·과잉 일반화를 진단하기 위한 독립 절차로 마련한다. 주석자 수와 역할은 미정이며 독립 주석과 합의 전 기록을 보존할 계획이다. 사람이 의미를 수정한 레코드는 별도 출처로 저장한다. 사람이 고친 레코드를 주 자동 조건에 대체하거나 그 결과를 자동 시스템 성능으로 보고하지 않는다.

### 3.3. 분할과 평가 자료 격리

개발·검증·시험은 계열 및 상위 파생 그룹을 기준으로 나눈다. 프롬프트와 렌더러, 주석 규칙, 임계값을 수정하는 데 쓴 자료는 개발 자료로 취급한다. 실제 분할 비율과 시험 계열은 자료 감사를 거쳐 결정하며 지금 고정된 것으로 서술하지 않는다.

시험 계열의 지원 예시는 추론 시 제공할 수 있다. 따라서 이 설정은 개발에 사용하지 않은 계열의 지원 예시를 이용하는 적응이며, 지원 없는 zero-shot이나 모델이 처음 보는 유행어라고 표현하지 않는다. 시험 평가 상황·평가용 정답·평가 결과는 구조 추출과 프롬프트 개발에 사용하지 않는다. 지원 풀을 먼저 고정하고 평가 상황을 별도로 작성·검토한다. 상황은 목표 응용문을 보고 역작성하지 않으며, 계열 관계·원본 중복·상황 근접 중복을 함께 점검한다. 계열 분리만으로 모델 사전학습 데이터의 오염이 제거되었다고 주장하지 않는다.

## 4. 계획된 방법과 비교 조건

### 4.1. 자동 추출과 결정적 렌더링

계열 원형 후보와 허용된 지원 텍스트·관찰 문맥을 입력하여 자동 레코드를 추출한다. 추출 과정에는 평가 상황 파일을 전달하지 않는다. 원응답·파싱 결과·모델 버전·실제 파라미터·입력 해시·오류·재시도를 기록하고, 계열별로 고정한 자동 레코드를 여러 상황에서 재사용한다. 형식 검증을 통과해도 근거 없는 의미 일반화가 남을 수 있으므로 이를 오류 분석 대상으로 유지한다.

동일 레코드를 두 렌더러로 변환한다. 서술형은 별도 LLM의 자유 요약으로 만들지 않고 고정 문장 틀을 사용한다. 필드형과 서술형에서 원자 사실·근거 ID·확실성·빈 목록을 대응시키고 항목 순서와 한국어 표시 어휘를 맞춘다. 이 결정적 변환은 정보 누락을 점검하기 위한 통제이며 사람이 자유롭게 쓴 모든 서술형 설명을 대표하지 않는다.

### 4.2. 고정 계열 생성 실험

| 조건 | 입력 | 비교에서의 역할 |
|---|---|---|
| B1 원자료 | 상황 + 고정 계열의 원문·지원 용례·관찰 문맥 | 원자료 기준선 |
| B2 서술형 | B1 + 자동 레코드의 결정적 서술형 표시 | 같은 자동 정보를 일반 문장 틀로 제공하는 통제 |
| B3 필드형 | B1 + B2와 동일한 자동 레코드의 필드별 표시 | 명시적 구조·맥락 표현 조건 |

모든 조건에서 생성 모델과 버전, 상황, 계열, 지원 순서, 공통 시스템 지시, 생성 기회 수와 출력 길이 제한을 맞춘다. 실제 지원 파라미터와 비결정성을 기록하며, 요청한 seed만으로 동일 출력을 보장했다고 쓰지 않는다. 좋은 출력만 선택하거나 특정 조건만 품질 개선을 위해 재생성하지 않는다. 기본 주실험에는 별도의 후보 재순위화·검증기·미세조정을 넣지 않는다.

주 비교 **B3−B1**은 자동 추출 정보의 추가와 표현 방식이 포함된 방법 차이다. **B3−B2**는 같은 레코드 사실을 제공했을 때 특정 서술형·필드형 렌더링의 차이다. **B2−B1**은 서술형 자동 정보 추가에 관한 보조 비교다. B3−B1을 JSON 서식만의 효과라고 부르지 않는다. 실제 입력·출력 토큰과 길이를 기록하고, 토큰 수를 억지로 맞추기 위한 무관한 문구 추가나 조건별 원자료 절삭은 하지 않는다.

### 4.3. 비용, 실패와 별도 시스템 평가

B1에는 사전 추출 호출이 없으므로 전체 비용이 같지 않다. 계열별 일회성 추출비와 상황별 생성비, 레코드 재사용 횟수를 구분한다. 실제 호출 이전에 모델별 지원 파라미터와 비용 상한을 확정한다. 예산 미정 상태에서 대량 유료 호출을 수행한 것으로 서술하지 않는다.

추출 실패로 B2/B3 생성이 불가능해진 경우도 계획 항목과 실패 원인을 남긴다. 사람이 레코드를 작성하여 실패를 없애지 않는다. 호출 오류, 형식 오류, 빈 출력, 거절, 원자료 부족과 평가자 무응답은 별도 상태로 저장한다. 성공한 출력만 남긴 표가 전체 시스템의 신뢰성을 대표하지 않도록 모든 계획 요청의 분모를 보존한다.

검색·추천은 상황으로 적합한 계열을 선택하는 별도 과제다. 후보 집합과 복수 적합 계열의 기준을 정한 뒤 별도 평가하며, 검색 후 생성하는 전체 시스템도 별도로 보고한다. 고정 계열 주실험의 개선을 검색 개선으로, 검색 지표의 개선을 생성 품질 개선으로 대신 해석하지 않는다. 검색 모듈과 사람 검토 레코드 조건은 준비·검증 범위를 확인한 뒤 추가 실험 여부를 결정한다.

## 5. 계획된 평가와 분석

### 5.1. 사람 평가

주요 지표는 **상황 적합성**과 **밈 정체성 보존**이며 각각 1–5점 기준을 사용한다. 상황 적합성은 발화 의도·관계·매체·요청 톤과의 부합 정도, 정체성 보존은 원 계열의 식별 가능한 특징과 핵심 함의 유지 정도를 측정한다. 자연스러움과 사용 의향은 보조 지표이며 재미는 선택 탐색 지표다. 문자열 일치나 모델 자기평가를 주요 지표의 대체물로 사용하지 않는다.

평가자는 조건명과 모델명을 모른 채 응용문을 평가한다. 첫 블록은 상황과 생성문만 제시하여 상황 적합성 등을 평가한다. 해당 평가자에게 배정된 모든 첫 블록 문항이 끝난 다음, 공통 원문·지원 자료를 제시하여 정체성을 평가한다. 자료를 본 뒤 이전 상황 점수를 수정하지 못하게 운영한다. 출력마다 곧바로 원문을 공개하면 다음 출력의 사전 평가가 영향을 받을 수 있으므로 블록 전체를 분리한다.

자료 제시 후 정체성 평정과 원자료 없이 자발적으로 계열을 인식하는 정도는 다른 측정이다. 자발적 인식·친숙도를 추가 수집하면 노출 시점과 자기보고의 한계를 명시한다. 자동 레코드는 정체성 정답으로 공개하지 않는다. 판단 자료가 부족하면 ‘판단 불가’를 허용하며 임의의 중간 점수를 넣지 않는다.

대상은 한국어 상황과 표현을 판단할 수 있는 20대 중심 표본을 계획하지만 정확한 참여 기준·인원·보상·모집 경로는 미정이다. 연구자 자신의 연령과 사용 경험은 독립 평가자 확보를 대신하지 않는다. 지인 또는 대학생 편의 표집을 선택하면 모집 경로와 관계, 필요한 범위의 언어·매체 경험을 기록하고 결과의 일반화 범위를 제한한다. 주석·프롬프트 개발 참여자와 최종 평가자는 가능한 한 분리하고 겸임·자료 노출을 보고한다. 모집 전에 기관의 동의·심의 적용 절차와 개인정보 보관 범위를 확인한다.

### 5.2. 분석 계획과 오류 진단

파일럿은 추출 근거성, 평가 지침의 이해 가능성, 실패 양상, 평가 시간과 비용을 점검하기 위한 개발 단계다. 파일럿의 소수 사례를 본실험의 효과 입증이나 검정력 보장으로 사용하지 않는다. 본실험의 표본과 분석 계획은 파일럿 후 시험 결과를 보기 전에 잠근다.

분석의 기본 제안은 동일 상황의 조건 차이를 짝지어 계산하고, 계열별로 요약한 뒤 계열에 동일 가중치를 주는 것이다. 같은 상위 파생 그룹에 속한 계열·상황·조건은 함께 재표집하는 방식의 기술적 구간을 검토한다. 여러 상황·반복 출력·평가자 점수를 모두 독립된 계열 표본으로 세지 않는다. 평가자 변동을 포함하지 않은 구간의 한계를 밝히고, 자료와 배정 구조가 허용하면 순서형 혼합효과 분석을 보조로 검토한다.

B3−B1의 두 주요 지표에 대한 검정 묶음과 다중 비교 처리, B3−B2의 사전 비교/탐색 지위, 결측 처리, 일치도 통계량은 사전에 확정할 항목이다. Holm 조정이나 순서형 Krippendorff's alpha는 현재 후보이며 확정·실행된 분석이 아니다. 홍소람(2025)이 보고한 코더 일치도는 단순 일치율이므로 이를 본 연구의 chance-corrected 일치도 근거로 바꾸어 인용하지 않는다. [홍소람, 2025, 196쪽](https://www.accesson.kr/kosim/assets/pdf/55396/journal-42-1-183.pdf)

품질 점수와 함께 모든 계획 요청의 추출·생성 성공률, 평가 가능률, 누락 이유를 보고한다. 실패를 최저점으로 처리하는 민감도 분석을 채택하더라도 실제 사람의 1점 평정과 구별한다. 원형 인식 손상, 상황 충돌, 함의 변경, 조사·어미 오류, 억지 치환, 말투 소실, 대화 순서 손상, 지원 근거 없는 일반화를 복수 오류로 기록할 수 있다. 자동 추출 오류와 생성 점수의 연관성을 분석하더라도 오류가 단독으로 원인임을 입증했다고 해석하지 않는다.

두 주요 지표가 함께 개선되었다는 결론은 각각의 결과가 뒷받침할 때만 쓴다. 차이가 명확하지 않으면 효과가 없다는 동등성 결론으로 바꾸지 않는다. 조건 간 동등성이나 비열등성을 검토하려면 별도 사전 기준과 적절한 분석이 필요하다.

## 6. 현재 구현 상태와 한계

현재 저장소에는 출처 메타데이터, 주석·분할·평가 지침, 자동 추출·생성 프롬프트, 오프라인 요청 생성·검증 기반이 마련되어 있다. 합성 fixture는 코드 경로 점검에 사용되며 실제 유행어 데이터나 모델 실험 결과가 아니다. 실제 호출 어댑터·확정 모델 설정·평가자 배정·설문 접근 제어·확증 통계는 각각 구현과 실행 증거를 확인하여 보고해야 한다. 파일 분리와 해시만으로 사람의 자료 노출이나 의미적 누출이 자동 방지되지는 않는다.

본 연구가 갖는 예상 한계는 다음과 같다. 첫째, 공개 텍스트로 확인 가능한 유행어를 선택하면 음성·동작에 강하게 의존하는 표현이 과소대표될 수 있다. 둘째, 20대 중심 편의 표본의 결과는 전체 한국어 사용자나 다른 연령층으로 일반화할 수 없다. 셋째, 지원 용례와 자동 추출 정보에 오류와 출처 편향이 남을 수 있다. 넷째, 알려진 유행어가 사전학습에 포함되었는지 완전히 확인하기 어렵다. 다섯째, B2/B3의 사실 대응은 토큰화·프레이밍·인지적 정보량의 완전한 동일성을 뜻하지 않는다. 여섯째, 단일 모델만 실행하면 결론은 해당 모델·버전·설정으로 제한된다.

추가로 현재 문헌 검토는 인수인계 목록과 직접 관련 문헌에 대한 표적 검토이며 체계적 문헌고찰이 아니다. 일부는 초록 또는 최종본과 대조하지 못한 저자본만 확인했다. 이 범위에서 기존 연구가 특정 실험을 전혀 하지 않았다는 전면적 부재 주장을 하지 않는다. 공개 원문을 읽었다는 사실은 수집 자료의 모델 입력·재배포 허가를 의미하지 않는다. 자료·코드 공개 진술과 생성형 AI 사용 공개는 확정 투고처·기관 규정과 실제 작업 기록에 맞춰 작성한다.

## 7. 결과 및 논의

**미작성: 실험 후.** 실제 원출력·독립 평정·잠근 분석 코드에서 재생성한 결과만 삽입한다. 가상 성능표·임의 효과 크기·선별된 성공 예문으로 이 절을 채우지 않는다.

## 8. 결론

**미작성: 실험 후.** 연구 질문의 답, 효과의 범위와 상충, 실패율, 일반화 한계가 실제 결과와 일치하는지 확인한 뒤 작성한다.

이 문서의 주장과 근거는 [claim_evidence_map_v01.json](claim_evidence_map_v01.json)에 연결했다. 국제 문헌은 [기존 출처 기록](../data/literature/international_sources.json), 국내 원문은 [새 원문 기록](../data/literature/domestic_fulltext_sources.json)을 기준으로 삼았다. 준비 상태를 인용하는 로컬 파일은 [실험 설계](../docs/experiment_design.md), [평가 지침](../docs/evaluation_protocol.md), [결정 기록](../docs/decisions.md)이다. 해당 파일의 계획과 실제 구현·실행 결과는 별도 증거이며, 제출 전 최종 버전으로 다시 감사해야 한다.
