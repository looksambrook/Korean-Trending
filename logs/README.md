# YouTube 방법 조사 및 새 실행 로그

2026-09-15 생성. 기준 장부는 `research.sqlite3`, 실제 수집을 포함한 최신 읽기용 내보내기는 `research_20260915_collection_v02.jsonl`이다. 초기 `research.jsonl`은 이전 조사 단계의 사본으로 보존한다. 기존 실험을 복구한 것이 아니라 이번 공식 문헌 조사·접근 점검·로컬 준비부터 기록한다.

## 실제 수집·기능 개선 후속 기록

- YouTube 공식 공개 피드 3개에서 실제 영상 메타데이터 45건 수집. 소켓 권한 실패와 권한을 바꾼 명시적 재시도를 모두 남겼다.
- 반복 안내문 억제, 한 단어 해시태그 처리, D0 빈도 순위·D1 초기 구현 분리. 첫 추출기의 누락과 개발 중 조건 보정 결과를 보존했다.
- 이름을 지정한 공개 검색 HTML 1회에서 결과 20건, 그중 영상 3개의 최초 HTML에서 전체 설명·채널·게시 시각을 수집했다. 원본 45건과 별도 사후 확장이다.
- 원 제작자의 패러디 소개를 확인하는 AI 보조 검토를 v01→v02→v03로 보존했다. 새 해석의 이용 가능 시각을 실제 생성 시각으로 기록했다.
- Google Trends 한국 공개 RSS를 1회 읽어 주제 10개를 수집했다. 검색량 문자열과 관련 뉴스 메타데이터만 보관하고 YouTube 지표와 합산하지 않았다.
- 실제 원본→후보→검색→제작자 설명→로컬 보고서 통합 실행은 기존 수집본을 재사용해 추가 HTTP 0회로 마쳤다.
- 새 수집·추출·묶음·검색 기능의 합성 검사 76개와 실제 피드 원문 45건 대조를 `youtube_delivery_validation_v01.json`에 기록했다. 통합 보고서 확인은 `youtube_integrated_report_check_v01.json`이다.

실제 자료 경로와 로그 ID는 [수집 기록](../docs/youtube_collection_run_v01.md), 실행 방법은 [키 없는 수집 안내](../docs/keyless_collection_guide.md)에 있다. 수집과 자동 처리의 선등록은 코드에 내장했다. 도구 기반 일부 문헌·접근 조사, 개발 도중 개별 테스트는 사후 기록 또는 개발 점검이라고 구분했다.

## 초기 조사 단계에서 기록한 범위

- 공식 YouTube API·권한·쿼터·분석/보존 문서 26개 URL 검토. 본문 확인 범위는 `data/research/youtube_access_sources_v01.json`에 있다.
- 핵심 6편과 보조 1편의 논문 본문 핵심 절 검토. 전문 정독·코드 재현으로 기록하지 않았다.
- Charts·Google Trends·공식 트렌드 보고서 소개 페이지 검토와 공개 화면 접근 시도. Charts 항목은 읽지 못했고 브라우저 도구는 연결 가능한 브라우저가 없다고 반환했다. 이 접근 시도는 실패로 남겼다.
- 로컬 통합 테스트 77개 통과. 가짜 모델 응답과 임시 테스트 DB, 기존 로컬 HTTP 테스트를 사용했으며 실제 YouTube/API 모델 호출은 없다.
- 파일럿 비용·쿼터·작업량 산식 계산. 실제 자료량·성능·사용 비용이 아니다.
- 같은 입력·설정·코드·프롬프트로 출력 경로만 바꾼 계획 실행이 차단되는지 확인. 종료 코드 2, 새 파일 없음, 기존 산출물 해시 동일을 검증했다.

## 로그 구축 초기 점검

로그 자체를 구현하는 동안 수행한 조사와 개별 테스트는 사전 등록이 불가능했으므로 사후 기록이다. 관련 명세에 `retrospective_registration=true`를 표시했고 자동 시작 시각은 등록 시각이다. 통합 테스트와 계획 산출·중복 차단 검증은 실행 전에 등록했다.

초기 로그 단위 테스트에서는 Windows 테스트용 SQLite 연결이 닫히지 않아 임시 폴더 정리 오류 7건이 발생했다는 구현 담당 에이전트의 보고가 있었다. 테스트에서 연결을 명시적으로 닫도록 수정한 뒤 해당 13개 테스트가 통과했다. 이 초기 실패의 원시 콘솔 파일과 수정 전 코드 해시는 보관되지 않았으므로 이를 완전한 재현 기록이라고 하지 않는다. 현재 코드에 대한 통합 테스트 원문은 `integrated_validation_v01.txt`에 보관했다. 계획 계산기 개별 테스트 5개도 구현 중 통과했으며 최종 통합 77개에 포함된다.

## 재실행 전 확인

프로젝트 루트에서 `python -B src/research_log.py list` 또는 `check --spec logs/specs/<명세>.json`을 사용한다. 실행 전 `begin`이 성공해야 후속 작업을 시작한다. 기존 생성 실행기까지 자동 보호되는 것은 아니다.

접근 실패의 환경이 그대로이면 같은 시도를 반복하지 않는다. 새로운 브라우저 연결, 확인된 프로젝트 접근, 공식 문서 개정, 수정된 코드·자료처럼 다음 판단을 바꾸는 근거를 먼저 기록한다. 완료·실패 기록을 지우거나 임의 시각을 추가해 중복 차단을 피하지 않는다.

모르는 현금 비용은 `null`이다. 실제 공개 자료 수집은 위 후속 기록대로 수행했고, 공식 Data API·통제된 모델 이해 실험·사람 평가는 아직 실행하지 않았다. 수집 성공을 전체 연구 성능으로 해석하지 않는다. 원문은 별도 수집 폴더에 보관하고 이 장부에는 출처·조건·결과 파일의 해시를 남긴다. 인증정보는 기록하지 않는다.
