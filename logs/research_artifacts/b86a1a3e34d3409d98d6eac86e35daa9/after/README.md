# 변화하는 멀티모달 밈을 활용한 콘텐츠 제작: RAG와 파인튜닝 비교

현재 연구 방향은 [RESEARCH_HANDOFF.md](RESEARCH_HANDOFF.md)의 **현재 우선 지침**을 기준으로 한다. 수집된 밈이 있다고 가정하고, 텍스트·이미지·음성·영상 자료를 활용한 콘텐츠 제작에서 **문맥/RAG와 실제 파인튜닝**을 비교한다. 밈의 변화에 따른 품질·새 용법 반영·기존 용법 유지·갱신 비용을 평가한다. 최종 제작물 범위는 **영상·이미지·글**로 확정했다. 사용자는 실험 자료의 준비가 필요하다고 답했으며, 모델·연산 환경·비용 상한과 제작물의 세부 규격은 아직 미정이다.

[비교 실험 설계](docs/multimodal_creation_protocol_v01.md) · [실험 설정 초안](configs/multimodal_creation_study_v01.json) · [모델 가능성 검토](docs/multimodal_model_feasibility_v01.md) · [관련 원문 검토](docs/multimodal_creation_literature_v01.md)

현재는 데이터 준비와 실행 설계를 진행 중이다. **실제 RAG–FT 제작 비교·독립 평가 결과는 아직 없다.** 준비 작업이나 테스트 통과만으로 연구를 완료 처리하지 않는다. 실패를 포함한 실험 기록은 `logs/research.sqlite3`에 보존하고 동일 명세의 재실행을 제한한다.

## 보존된 밈 발견 도구와 이전 진행 기록

아래 내용은 목표 변경 전 수집·발견 작업의 기록이다. 이번 제작 비교 실험의 결과와 구분한다. 변경 전 README의 [원본 사본](docs/history/before_multimodal_creation_20260915_v01/README.md)을 보존했다.

**최근 교정:** 사용자가 원하는 것은 밈의 발견이다. 일반 급상승 검색어를 밈 탐색 결과로 제시한 이전 응답은 목표에 맞지 않았다. Google Trends 수집본은 당시 시도의 기록으로 보존하며 밈 후보·밈 발견 성공에 포함하지 않는다. 반복 빈도만 있는 인명·방송명·뉴스 주제도 밈으로 표시하지 않는다. 현재는 실제 인용·모방·변형 용례와 그 문맥을 확보하는 작업을 진행한다.

## 지금 실행하기

```powershell
python -X utf8 -B src/find_memes.py
```

밈 이름이나 후보 ID 없이 공개 관찰→검색어 자동 선정→추가 용례 수집→계열 연결→근거·쓰임 보고서를 실행한다. [사용법](docs/meme_finder_usage.md) · [실제 자동 실행 결과](docs/meme_finder_run_20260915.md) · [결과 보고서](data/derived/meme_finder_delivery_20260915_v01/report.html)

2026-09-15 최종 실행은 새 피드 45건에서 출발해 공개 GET 20회로 상세 용례를 모았고, 비교 문장·반복 유행어·공연 패러디 3개 계열의 텍스트 근거를 연결했다. 자동 선정한 나머지 표현 1개는 보류했다. 독립 정답 평가나 영상·음성 분석이 완료됐다는 뜻은 아니다. 선택적인 로컬 LLM 단계는 메모리 부족으로 실행되지 않았으며, 현재 보고서의 쓰임은 코드가 실제 구문·제작자 설명에서 정리한 것이다.

## 최근 사용자 지시

- YouTube에서 자료 접근과 밈 발견·이해 가능성을 먼저 확인한 뒤 다른 플랫폼으로 확장한다. 다중 플랫폼 목표는 유지한다.
- 별도 연구·기관 접근 권한이 없는 개인 개발 환경이다. 접근 가능 필드·범위·비용은 조사 전이므로 가정하지 않는다.
- 서버가 필요하면 용도·사양·비용을 먼저 제시한다.
- 고정 완료일 대신 밈을 발견하고 의미·사용 맥락을 파악할 수 있는지 실제 평가로 확인한다. 구체적인 성공 기준은 파일럿 설계에서 제안한다.
- 예산, 연구 기간, 평가자 규모와 투고처는 미정이다.
- 2026-09-15 공식 공개 피드를 통해 3개 채널의 실제 영상 메타데이터 45건을 수집했고 후보 추출·원문 보고서까지 실행했다. API 키는 없으며 Data API 실접속·통제된 모델 이해 실험·사람 평가는 아직 수행하지 않았다. 검증만 반복하지 않고 수집·발견 기능 개선을 우선한다.

`logs/research.sqlite3`가 기준 장부다. 새로운 실험은 프로젝트 루트에서 `src/research_log.py`로 먼저 등록하고, 같은 명세가 있으면 기존 결과를 확인한다. `src/youtube_pilot_plan.py`는 등록과 중복 차단을 내장한 오프라인 계획 계산기다. 기존 생성 실행기에는 새 로그가 자동 연결되지 않으므로 새 연구 실행에 그대로 사용하지 않는다.

실행 기록 조회: `python -B src/research_log.py list`. 실제 수집까지 포함한 조회용 사본은 `logs/research_20260915_collection_v02.jsonl`이며 내보내기 이후 추가된 실행은 SQLite에서 확인한다. 초기 `logs/research.jsonl`도 보존했다. 처음 로그 구현 중 수행한 문헌 조사·점검은 사후등록이라고 명시했다.

## 보존 자료와 사용 범위

- [최신 연구계획서](RESEARCH_HANDOFF.md): 원본 내용 보존.
- `data/literature/` 및 관련연구 문서: 기존 문헌과 열람 범위의 참고 자료. 최신 규정·가격·접근성 확인 결과로 간주하지 않는다.
- `data/evidence/` 및 원자료 검토 문서: 기존에 알려진 사례의 출처 조사 자료. 이름을 미리 지정하지 않고 발견한 결과나 새 파일럿 평가 자료로 간주하지 않는다.
- `src/`, `tests/`, `prompts/`, `data/fixtures/`, `data/schemas/`, `data/templates/`: 기존 코드·테스트·양식. 합성 테스트 입력은 소프트웨어 검증용이며 실험 실행 결과가 아니다.
- `configs/smoke.json`: 오프라인 테스트 설정. `configs/model_candidates.json`: 과거 모델 후보 조사.
- `docs/experiment_design.md`, `docs/annotation_guidelines.md`, `docs/data_schema.md`, `docs/split_protocol.md`, `docs/model_execution_options.md`, `docs/paper_suitability_review.md`, `paper/`: 이전 생성 연구의 방법·문헌·원고 참고자료. 새 연구의 실행 계획이나 확정 조건이 아니다. 이 문서 안의 이전 실험 경로·규모·일정은 현재 유효하지 않으며 일부 참조 파일은 삭제되었다.

기존 생성 코드는 B1/B2/B3 설계를 따른다. 현재 새 경로는 `src/youtube_watch.py`가 공개 피드 수집→후보 추출→로컬 보고서를 연결한다. D1은 독립 사용·의미 검증이 미완성인 초기 구현이다. 원래 다중 플랫폼 목표와 D0/D1 × U0/U1 계획은 유지하며, 현재 수집 성공을 모델 이해나 전체 연구 완료로 해석하지 않는다.
