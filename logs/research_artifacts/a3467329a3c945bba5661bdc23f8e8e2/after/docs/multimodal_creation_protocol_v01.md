## 1. 연구 질문과 비교의 단위

주질문은 “같은 기반 모델과 같은 시점까지 확보한 밈 자료를 사용할 때, 검색·문맥 제공과 실제 미세조정이 새 제작 요청에서 밈의 특징·사용 맥락·현재 의미를 얼마나 보존하며, 갱신 비용과 지연은 어떻게 다른가?”다. 주효과는 `RAG − FT`의 제작 결과 차이다. 기억 추가 없는 기준선과의 차이도 함께 보고한다.

실험 항목의 식별자는 `(replicate_id, snapshot_id, brief_id, arm_id, generation_repeat, output_format)`이다. 동일 요청을 모든 주조건에 배정한다. 계열·상위 파생 그룹 안의 여러 요청, 여러 프레임, 여러 평가자를 독립적인 밈 표본 수로 세지 않는다. 생성 반복 수와 학습 반복 수는 다른 변수이며 파일럿 뒤 별도로 확정한다.

주과제 후보로 목표 계열과 제작 맥락을 고정한 **계열 조건부 콘텐츠 제작을 제안한다**. 과제 선택은 아직 확정하지 않았고 설정의 `primary_task`는 `null`이다. 이 제안을 선택하면 모든 조건에 같은 최소 계열 단서와 요청을 주되 실제 정답 작품·평가 척도 답·평가용 해설은 주지 않는다. 기준선도 사전학습에서 해당 계열을 알 수 있으므로 “밈을 전혀 모르는 모델”이라고 부르지 않는다. 계열 선택까지 필요한 자유 제작도 선택 가능한 과제이며, 선택할 경우 검색 성공과 제작 품질을 분리한다.

## 2. 조건과 통제

| 조건 | 제작 시 모델·입력 | 갱신 방식 | 해석 |
|---|---|---|---|
| C0 기억 추가 없음 | 고정 기반 모델 θ0 + 공통 제작 요청 | 연구 자료로 추가 학습·검색하지 않음 | 외부 기억을 추가하지 않은 기준선. 사전학습 지식 부재를 보장하지 않음 |
| CR RAG/문맥 | 같은 θ0 + 공통 요청 + 시점별 허용 인덱스에서 검색한 자료 | 자료·표현·인덱스 갱신 | 문맥 기반 지원 효과. 가중치 학습이라고 쓰지 않음 |
| CF 미세조정 | 같은 θ0에서 출발한 θT 또는 θ0+학습 어댑터 + 공통 요청 | 허용 학습 자료로 파라미터 갱신 | 실제 최적화 단계와 파라미터 아티팩트가 있어야 FT로 집계 |
| CRF 선택 진단 | CF + CR과 같은 검색 규칙 | 두 방법 병용 | 선택한 경우에만 추가. CR과 CF의 비교를 대체하지 않음 |

공통 기반 모델의 정확한 버전·가중치 해시·토크나이저·미디어 전처리 버전을 고정한다. FT가 다른 모델에서만 가능하다면 같은 모델을 비교했다는 주실험을 실행할 수 없다. 다른 모델 간 비교는 별도 시스템 비교다. 프롬프트로 “학습한 것처럼 답하라”고 지시하거나 RAG 레코드를 저장하는 것으로 CF를 대체하지 않는다.

각 시점에서 CR과 CF가 이용할 수 있는 **적응 자료의 전체 풀**은 같다. 학습용 요청–목표 쌍을 새로 작성하거나 합성한다면 그 동일 쌍을 CR에도 검색 가능한 자료로 제공하고 작성·검수 비용을 기록한다. 합성 목표를 독립 정답으로 사용하지 않는다. CR은 검색한 일부를, CF는 여러 학습 단계에서 자료를 볼 수 있으므로 실제 노출량·순서·반복 횟수까지 같다고 주장하지 않는다. CR의 검색·재순위화·문맥 길이와 CF의 학습 예산·체크포인트 선택은 개발 자료에서 정하고 잠근다.

같은 요청 형식, 시스템 지시의 공통 부분, 제작 횟수, 출력 한도, 후처리, 재생성 정책을 사용한다. 조건별 추가 입력과 효과적 디코딩 설정은 모두 저장한다. 특정 조건의 나쁜 결과만 다시 만들거나 사람이 수정해서 대체하지 않는다. 네트워크 재시도, 형식 복구, 창작적 재생성을 각각 기록한다.

## 3. 멀티모달 입출력과 공통 제작기

`input_modalities`와 `output_format`은 별도 축이다. 밈 입력이 영상이라고 해서 결과가 반드시 영상인 것은 아니며, 영상 메타데이터를 읽었다고 영상 내용을 관찰한 것이 되지 않는다. 최종 출력 형식은 사용자와 모델 접근 범위가 정해진 뒤 선택한다.

| 실험 층 | 허용 입력과 실제 생성 | 결과에서 허용하는 주장 |
|---|---|---|
| native | 모델이 실제 이미지·음성·영상 내용을 지원된 방식으로 받으며, 선택한 출력 형식을 직접 생성하거나 학습함 | 실제 접근한 모달리티·학습 대상·출력에 한정한 결과 |
| proxy | OCR·ASR·캡션·선택 프레임 등 고정 변환 결과를 모델에 제공 | 해당 대리 표현을 이용한 제작. 원영상의 동작·타이밍·음향을 모두 이해했다고 주장하지 않음 |
| planner_renderer | 조건별 모델이 공통 제작 계획 스키마를 출력하고 같은 고정 제작기가 이미지·음성·영상을 생성 | 지식 적응을 적용한 계획 모델과 공통 제작기를 포함한 시스템 결과. 제작기 가중치를 FT했다고 주장하지 않음 |

native와 proxy 결과는 섞어서 단일 “멀티모달 성능”으로 만들지 않는다. 동일 소스의 native/proxy를 비교할 수 있으면 짝지어 별도 보고한다. 지원되지 않는 조합은 지원 불가로 기록한다. 사용 가능한 조합만 남긴 분모와 애초 계획한 조합의 분모를 함께 보고한다.

공통 제작기를 쓰면 모델·버전·입력 템플릿·화면 규격·음성/음악 설정·길이·프레임률·안전 설정을 조건 간 고정한다. 가능한 경우 같은 렌더링 seed를 사용하지만 결정성을 보장한다고 쓰지 않는다. 계획 출력의 품질과 실제 완성물 품질을 각각 평가한다. 계획 JSON이나 영상 대본만 생성했다면 이미지·음성·영상 완성물을 제작했다고 집계하지 않는다. 실행 불가능한 계획과 제작기 실패도 해당 조건의 결과다.

## 4. 실행 가능한 데이터 계약

파일은 UTF-8 JSONL, 아티팩트는 읽을 수 있는 로컬 경로 또는 명시적으로 접근 가능한 저장 위치로 전달한다. `null`은 미확인·미결정이며 빈 문자열이나 가짜 경로로 채우지 않는다. 아래 연구 테이블은 실행 manifest와 연결해 관리할 최소 정보다. 모든 필드를 현재 적재기에 그대로 전달할 수 있다는 뜻은 아니다.

현재 로컬 적재기의 실행 입력은 [multimodal_meme_dataset.py](../src/multimodal_meme_dataset.py)와 [레코드 스키마](../data/schemas/multimodal_meme_record.schema.json)가 정의하는 **중첩 레코드 JSONL**이다. 각 레코드는 `meme_id`, `family_id`, `version`, `available_at`, nullable `published_at`, `provenance`, 비어 있지 않은 `assets`를 갖는다. `relationships`, `knowledge`, `annotations`, `creation_examples`는 배열이다. 자산에는 `asset_id`, `source_group_id`, nullable `source_url`, 프로젝트 안의 `local_path`, `sha256`, `mime`, `modality`, `license_or_use_basis`, `status`, `provenance`, `purpose`와 선택적 `parent_asset_ids`를 사용한다. 실제 지원하는 필드·열거값은 스키마를 따르며 외부 URL만 적고 자산을 읽었다고 처리하지 않는다.

`creation_examples`의 실행 필드는 `example_id`, `brief`, `target_asset_ids`, `target_text`, `available_at`, `provenance`, `purpose`, nullable `split`이다. `purpose=training_supervision`과 `evaluation_only`를 구분한다. 학습용 목표와 평가용 목표를 같은 이름의 파일에 섞어 조건 어댑터에 넘기지 않는다. 주석의 `author.type`, `role`, `human_minutes`와 지식의 `purpose`를 보존한다. 적재는 원본 바이트를 복사하고 `records.jsonl`·`manifest.json`을 만들며 수집·전사·생성·평가를 대신하지 않는다.

아래 표는 그 중첩 자료와 실험 전용 요청·잠금 정답·실행 산출물을 정규화해서 보관할 때의 계약이다. `assets.jsonl` 등은 연구 테이블 이름이며 현재 명령이 이미 모두 생성한다는 주장이 아니다. 계열·원출처 그룹·모달리티 연결과 두 분할 축을 실제 실행에서 보존하는지는 G0/G3에서 별도로 확인한다. 구현의 임시 자동 분할 비율을 본실험 비율이나 표본 수로 승격하지 않는다.

| `runs.jsonl` 및 실행 manifest | `run_id`, `item_id`, `arm_id`, `snapshot_id`, 코드·프롬프트·설정·기반 모델·체크포인트·인덱스·입력 해시, 실제 파라미터, 원응답/생성 파일, `status`, `error`, `retry_of`, 비용·시간·토큰/미디어 사용량 |

`provenance`는 `actual_collected`, `researcher_authored`, `ai_synthetic`을 구분한다. 실제 웹 자료의 제작자가 AI를 썼는지 모르면 별도 `creator_generation_origin: unknown`으로 둔다. 주석·요약·OCR·ASR·모델 출력은 원자료의 provenance를 상속해 실제 관찰인 것처럼 바꾸지 않는다. 파생 레코드는 생성 모델·버전·처리 시각·입력 해시를 가진다. `allowed_uses`의 수집/보관/검색/학습/외부 전송/제작은 구분하며 미확인 용도를 허용된 것으로 가정하지 않는다.

JSONL 검사만으로 자료를 읽었다고 인정하지 않는다. 실행 전 각 자산의 실제 접근과 해시, 이미지 디코딩, 오디오 길이, 영상 프레임·오디오 트랙을 실제로 확인하고 검사 범위를 기록한다. 필요한 모달리티를 읽을 수 없으면 그 자산을 native 입력으로 세지 않는다.

## 5. 시간과 계열 분할

**시점 T 제한은 주실험의 불변 조건이다.** 모든 지원 자료와 현재 내용 버전의 `available_at`, OCR·ASR·캡션 등의 파생 표현, 계열 지식·연결의 `available_at`이 해당 스냅샷의 `source_cutoff` 이하여야 하고 `source_cutoff <= evaluation_at(T)`여야 한다. 게시 시각만으로 과거에 사용할 수 있었다고 판단하지 않는다. `valid_from`이 과거인 새 해설도 `known_at/available_at`이 미래라면 과거 입력에 넣지 않는다. 현재 모델로 과거 영상에 새 캡션을 붙인 자료도 이 규칙의 예외가 아니다. 평가 해설과 결과는 인덱스·학습 자료·프롬프트에 넣지 않는다.

주실험의 시간 모드 후보는 `prospective`와 `historical_artifact_replay`이며 아직 선택하지 않았다. prospective는 당시 이용 가능한 근거·연결·지식과 실제 완성된 모델/인덱스로 수행한다. historical_artifact_replay는 **그 T에 이미 존재했던 입력·파생물·모델·인덱스·FT 체크포인트의 고정 사본**을 그대로 사용하는 재실행만 뜻한다. 재실행한 출력의 생성 시각은 현재로 남기며 T 당시 실제 서비스를 실행한 관찰 결과로 쓰지 않는다. 후대 모델, 새 해설, 새 계열 연결, 새 OCR·ASR·캡션 또는 T 뒤에 학습된 체크포인트를 끼워 넣는 재구축은 이 replay에 포함하지 않는다.

후대 처리기를 과거 자료에 적용하는 것은 별도 `posthoc_processing_simulation`을 새로 설계했을 때만 가능하다. 그 경우 실제 처리 시각과 사용 버전을 명시하고 **T 당시 성능·갱신 지연·그때 이용 가능한 지식의 효과로 소급하지 않는다**. 이번 설정에서는 이 simulation을 선택하지 않았고 주실험 조건에도 포함하지 않는다. RAG 인덱스와 FT 체크포인트, 공통 기반 모델·제작기의 정확한 버전은 실제 이용 가능 시각을 가진다. T에 준비되지 않은 갱신은 T 평가에 이전 버전 또는 실패로 반영한다. 사후 생성한 평가 주석은 평가 전용으로 격리하고, 그 작성 시각을 과거 지식 버전으로 기록하지 않는다.

분할에는 서로 다른 두 축이 있다.

1. **방법 개발용 계열 분할:** `lineage_group_id`로 개발·검증·잠금 평가 계열을 분리한다. 같은 원본의 재게시, 음원, 프레임, 자막, 번역, 크롭, 리믹스가 다른 분할로 새지 않도록 `source_group_id`와 미디어 연결을 함께 묶는다. 공통 기능만으로 무관한 계열을 강제로 합치지 않는다.
2. **각 계열 안의 시간 역할:** 평가 계열의 과거 지원을 잠금된 적응 방법의 입력으로 CR과 CF에 모두 허용하는 방안을 제안한다. 이후 제작 요청·목표 결과·평가 주석은 제외한다. 이는 **개발에 사용하지 않은 계열의 허용 지원을 통한 적응**이며, CF가 해당 계열을 학습하지 않은 zero-shot 실험이라고 부르지 않는다. 단순히 “train/test 계열 완전 분리”라고 요약하면 잘못이다. 기존 적재기의 `train/dev/test` 내보내기는 train 계열만 적응 자료로 제공하는 준비 기능이다. 별도 [두 축 준비 모듈](../src/multimodal_creation_split.py)은 호출자가 `locked_family_past_support`와 잠금 평가 계열을 명시했을 때 과거 지원과 평가 역할을 나누어 내보낸다. 지원판과 평가판의 레코드 버전을 독립 선택하며 test 계열을 train으로 옮기지 않는다. AI 합성 입력의 집중 검사 4개를 통과했지만 실제 연구 자료·방법 잠금·모델 실행을 검증한 것은 아니다. 연구 설정의 선택 값은 계속 `null`로 유지한다. 구체 계약과 한계는 [사용법](multimodal_creation_split_usage.md)을 따른다.

지속 학습을 선택할 경우 **동일한 고정 partition manifest를 모든 스냅샷에서 재사용**한다. 고정 배정은 T0에서 이용 가능한 계열·원출처·모달리티 연결로 만들고 ID별 배정과 근거 해시를 보존한다. 미래 연결을 미리 읽어 T0 분할을 만들지 않는다. 이후 manifest는 기존 ID 배정을 바꾸지 않고 신규 ID와 충돌 기록만 추가하는 버전으로 연결하며, FT 체크포인트는 자신이 노출된 ID와 manifest 버전을 참조한다.

새 ID가 기존 하나의 분할에만 연결되면 그 분할을 상속한다. 어떤 기존 그룹에도 연결되지 않은 새 그룹은 사전 고정한 신규 그룹 배정 규칙으로 한 번만 배정한다. **새 연결이 서로 다른 기존 분할을 이어 붙이면 자동 병합·이동을 금지하고 해당 연결 성분의 적응 내보내기와 평가를 차단한다.** 충돌 ID·발견 시각·근거·과거 학습 노출을 `partition_conflicts.jsonl`에 남긴다. 과거에 학습한 자료를 test로 옮겨 계속 평가하지 않는다. 해결이 필요하면 새로운 분할 버전과 오염되지 않은 공통 기반 상태에서 별도 연구 반복을 시작하고 영향받은 이전 평가를 별도 표시한다. 데이터 삭제만으로 기존 FT 가중치에서 학습 흔적이 제거됐다고 간주하지 않는다. 고정 manifest 및 충돌 차단의 구현 증거가 없으면 지속 갱신 본실험은 실행 준비 완료가 아니다.

평가 계열의 점수를 보고 학습률·프롬프트·검색기·예산을 다시 고르면 그 계열은 개발에 사용된 것이다. 수정 후에는 새 잠금 평가가 필요하다. 기반 모델의 사전학습에 밈이 있었는지는 확인되지 않을 수 있으며 게시일만으로 비노출을 입증하지 않는다.

역할 분리에서는 골드의 동일 바이트·명시된 후손 파생물을 제외한다. 평가 작품이 같은 원출처 그룹에 속한다는 이유로 공개된 과거 부모 템플릿까지 역방향으로 골드라고 처리하지 않는다. 과거 지원에 포함한 동일 항목을 나중에 평가용으로 바꾸거나 다른 ID로 동일 요청–목표를 다시 넣는 경우에는 평가 재사용 충돌로 차단한다. 과거 지원은 소급 삭제하지 않는다. 이 검사는 명시된 ID·내용·파생 관계와 준비 이력에 근거하며, 실제 모델 노출 기록이나 의미상 중복 검토를 대신하지 않는다.

## 5.1. 현재 준비 기능의 확인 범위

[미디어 검사기](../src/multimodal_media_audit.py)는 텍스트 바이트, 이미지 픽셀, PCM WAV 샘플, OpenCV 영상 프레임을 한정된 범위에서 실제로 읽는다. [사용법](multimodal_media_audit_usage.md)에 전체/표본 읽기와 미지원 포맷을 명시했다. 영상의 오디오 트랙은 미검사이므로 영상 읽기 성공만으로 전 모달리티를 확인했다고 쓰지 않는다. 기존 이미지 3장의 픽셀 읽기와 원본 해시 보존을 확인했지만, 출처·밈 의미·모델의 처리 능력을 검증한 결과는 아니다.

[독립 주석·평가 지침 초안](multimodal_creation_annotation_guide_v01.md)과 [공통 제작 프롬프트 초안](../prompts/multimodal_creator_system_v01.txt)을 준비했다. 실제 사람 정답·평가 결과가 없고 프롬프트도 아직 모델에 실행하지 않았다. 이 준비 기능들이 존재하는 것과 G0–G5의 실제 연구 완료는 구별한다.

## 6. 갱신, 실행, 비용

개발 파일럿 뒤 고정할 시간 묶음은 초기 T0와 이후 T1…Tn이다. 실제 시각·횟수·간격은 미정이다. 각 갱신에서는 새 계열, 기존 계열의 의미/적합 맥락 변화, 기존 계열의 유지, 아직 해석이 불명확한 항목을 구분한다. 자연 관찰 자료가 없는 변화는 AI가 만든 예시로 채워 실제 변화처럼 보고하지 않는다.

갱신 경로 후보로 CR 인덱스를 순차 갱신하고 CF도 이전 체크포인트에서 순차 갱신하는 **동일 일정의 지속 적응을 제안한다**. 아직 선택하지 않았고 설정의 `primary_update_policy`는 `null`이다. 이 방안을 선택하면 독립 반복마다 동일 θ0와 빈 연구 인덱스에서 시작해, 고정 partition manifest와 엄격한 시점 조건을 지키며 전체 일정을 수행한다. 실제로 당시 수행한 반복과 현재 사본으로 수행한 시간 제한 재실행은 구분한다. 특정 조건만 평가 결과를 본 뒤 초기화하지 않는다. θ0에서 매번 재학습하는 FT 재구축과 전체 인덱스 재구축 비교도 선택 가능한 별도 방안이다. 지속 FT의 과거 자료 재생 정책·데이터 양·반복 수와 RAG의 과거 버전 보존/검색 필터는 선택 후 실행 전에 고정한다.

새 의미 적용과 함께 이전 의미가 여전히 적절한 요청을 넣어 불필요한 망각·과도한 최신화도 평가한다. 오래된 밈을 요청 맥락에 맞게 의도적으로 사용하는 것은 자동 오류가 아니다. 금지·수정된 맥락, 시점이 명시된 회고, 불명확한 사용을 독립 주석에서 구별한다.

비용은 `자료 준비 + 모달리티 변환 + 인덱싱/학습 갱신 + 제작 추론 + 공통 제작기 + 재시도/실패 + 사람 작업`으로 나눈다. RAG 비용에는 검색·임베딩·재순위화·문맥 토큰·저장, FT에는 학습 계산·체크포인트 저장·검증·재학습을 포함한다. 로컬 계산도 GPU/CPU 시간·메모리·가능한 전력 측정치를 기록하고 무료라고 가정하지 않는다. 미확인 단가는 `null`로 둔다.

실제 장부에는 최초 구축비, 갱신당 비용/완료 지연, 요청당 비용/지연, 누적 총비용을 각각 기록한다. 비용 분모는 계획 요청 수와 성공 출력 수를 함께 제공한다. 상각은 `총비용(N)=구축·갱신 고정비+N×요청당 변동비`로 계산하되 실제 관찰 범위 밖 N은 가정임을 표시한다. 고정 예산 비교와 최선 품질 비교는 다른 질문이며 나중에 예산을 맞춘 척하지 않는다.

## 7. 독립 평가와 실패 분모

정답은 생성 결과를 보지 않은 독립 주석자가 시점 제한 근거로 작성한다. 생성 모델의 자기 점수나 같은 LLM이 만든 해설을 독립 정답으로 사용하지 않는다. 사람 평가자 수·모집·보상은 아직 미정이다. 주석 지침 개발·사람 검수·합의 시간을 따로 기록하며 자동 레코드를 사람이 수정한 경우 별도 버전과 조건으로 남긴다.

| 지표 | 평가 대상 |
|---|---|
| 밈 특징 보존 | 핵심 문구·캐릭터·관계·동작·리듬·타이밍 중 해당 계열에서 필요한 요소. 해당하지 않는 모달리티 항목은 N/A |
| 요청·맥락 적합성 | 대상 독자·사용 장소·목적·형식·제약에 맞는 제작인지 |
| 콘텐츠 품질 | 읽기·보기·듣기의 완성도, 이해 가능성, 자연스러움, 내부 일관성. 창의성을 원본 복제와 구별 |
| 시점 적합성 | 요청의 시점과 의도에 맞는 의미/용법인지. 최신이라는 이유만으로 높은 점수를 주지 않음 |
| 잘못되거나 해로운 적용 | 폐기된 맥락, 실제 대상에 대한 부적절한 모욕·낙인, 오해를 유발하는 용법 등 주석 근거가 있는 오류 |
| 불명확성 처리 | 자료가 상충하거나 적절한 밈이 없는 요청에서 무리한 적용 대신 보류·중립 대안을 선택하는지 |
| 제작 성공 | 완성 파일의 존재·재생 가능성·형식·길이·필수 트랙/요소 충족. 대본만으로 영상 성공 처리하지 않음 |

평가자는 조건·체크포인트·검색 결과를 모르게 하고 결과 순서를 균형 배정한다. 실제 모달리티를 재생할 수 있는 평가 화면이 필요하다. 먼저 요청과 결과로 적합성·품질을 평가하고, 별도의 동일한 시점 기준 자료로 밈 특징·시점 적합성을 평가한다. 조건별로 다른 참고자료를 보여주지 않는다. 척도·동점·N/A·보류의 처리와 사전 친숙도 수집 방식은 개발 파일럿에서 잠근다.

계획한 모든 `(시점, 요청, 조건, 반복, 출력 형식)`을 분모에 남긴다. 입력 부재, 검색 실패, FT 실패, 내용 생성 실패, 형식 오류, 제작기 실패, 정책상 거절, 평가 결측을 서로 구분한다. 두 조건 모두 성공한 사례의 품질 비교는 보조 표다. 전체 계획 분모의 성공률과 사전 정의한 실패 처리/민감도 분석을 함께 보고한다. 부적절한 요청에서 정당한 거절은 무조건 창작 실패 최저점으로 넣지 않고 독립 적합성 기준으로 판단한다.

주분석은 잠금된 CR–CF 비교이고 C0 대비 차이를 함께 제시한다. 동일 요청을 짝지으며 계열/상위 그룹·시간·평가자 반복 구조를 반영한다. 최종 추정법, 신뢰구간 방법, 주요 지표, 다중 비교 처리, 최소 관심 효과와 표본 수는 파일럿의 분산·비용·평가 부담을 본 뒤 본실험 전에 고정한다. 파일럿 자료로 유리한 지표를 선택했다면 선택 과정을 공개하고 파일럿을 확증 결과로 재사용하지 않는다.

## 8. 실제 실험으로 진행하는 순서와 완료 기준

| 단계 | 실제 수행과 남길 증거 | 통과 조건 |
|---|---|---|
| G0 자료·실행 범위 확정 | 실제 assets/links/adaptation/brief 파일, 모델·출력·비용 상한, 과제·갱신 방식·시간 모드 선택, 접근 가능한 실행 경로 | 필요한 파일과 모델 기능을 실제 확인. 두 축 적응을 선택하면 미구현 역할 분리도 먼저 구현. 미확정 값을 임의로 채우지 않음 |
| G1 기능 파일럿 | 동일 실제 자료/요청으로 C0·CR·CF 제작을 실제 실행, 가능하면 최종 미디어까지 생성 | RAG 검색 아티팩트, 실제 FT 최적화 로그·변경된 가중치/어댑터, 각 조건의 원출력·완성물·비용이 존재 |
| G2 개발·주석 파일럿 | 독립 개발 요청과 주석으로 절차·품질·비용·시간 부담 측정 | 필요한 모달리티가 평가되고 실패가 분모에 보존됨. 파라미터·평가 설계 결정 근거가 있음 |
| G3 본실험 잠금 | 새 평가 계열·시간 스냅샷·요청·분석·모델/프롬프트/설정 해시, 고정 partition manifest와 충돌 차단 잠금 | 평가용 자료가 검색·학습 입력과 분리되고 주 비교가 사전 확정됨. 시점별 재분할과 학습 노출 뒤 test 이동이 차단됨 |
| G4 시점별 본실험 | 모든 계획 조건/요청을 실행하고 갱신·실패·사람 평가를 기록 | 계획 분모의 실행 상태가 모두 설명되고 실제 평가 자료가 있음 |
| G5 논문 결과 작성 | 데이터 흐름, 조건, 품질·갱신 비용, 불확실성·실패·한계를 재현 가능한 표로 작성 | 주장을 뒷받침하는 실제 관찰·생성·학습·평가 아티팩트가 연결됨 |

준비된 설정 파일은 [multimodal_creation_study_v01.json](../configs/multimodal_creation_study_v01.json)이다. 현재 단계는 G0 이전의 로컬 설계다. 실제 멀티모달 자료 묶음의 위치, 공통 기반 모델의 FT/입출력 가능 범위, 제작 형식, 계산·금액 상한, 독립 평가 운영 범위가 정해져야 해당 실제 실행을 시작할 수 있다. 확인된 범위 안의 로컬 구현·자료 검사는 계속할 수 있다. 이 문서나 설정의 생성, 빈 실행 파일, 합성 smoke test만으로 G1 이후를 완료 처리하지 않는다.
