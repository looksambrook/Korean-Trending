# 수집된 밈의 다중모달 적용: 모델·학습·자원 가능성 v01

확인일: 2026-09-15. 사전 등록한 문헌 검토 실행: `3ee560528cf8470b809fd64a03e6602b`.

이 검토는 **밈 자료가 이미 수집되어 있다는 가정 아래, 밈이 바뀔 때 문맥/RAG 갱신과 파인튜닝이 밈 기반 콘텐츠 제작에 미치는 영향을 같은 기본 모델로 비교**하기 위한 것이다. 한국어를 우선하고 텍스트·이미지·음성·영상 입력을 유지한다. 최종 제작물의 매체는 아직 정하지 않았다. 수집 확대나 기존 발견 성능 측정의 완료를 뜻하지 않는다.

공개 문서와 코드 본문에서 가능한 구현 경로를 확인했다. 아래 모델로 추론·훈련을 실행하지 않았고 가중치를 내려받거나 로드하지 않았다. 따라서 아래의 가능성은 이 프로젝트의 생성 품질·학습 성공·논문 결과에 대한 실증이 아니다.

## 공식 학습 예제에서 실제 읽은 범위와 바꿔야 할 부분

**Gemma3n:** [원문 코드](https://raw.githubusercontent.com/huggingface/huggingface-gemma-recipes/main/scripts/gemma3n_fine_tuning_on_all_modalities.py)의 입력 전처리, E2B BF16 로드, collator, `LoraConfig`, `SFTTrainer` 부분을 읽었다. 약 6개 시각 프레임을 고르고, 오디오를 16 kHz 단일 채널로 바꾼 뒤 최대 5초와 1.25배속을 적용한다. 원래 과제는 범주 예측이다. 이러한 변경은 밈의 리듬·억양·반전 순간을 잃거나 바꿀 수 있으므로 그대로 본 연구에 사용하지 않는다. 자료의 원래 시간축을 보존하고, 잘린 구간·프레임 시각·전처리 버전을 기록하는 collator와 제작물용 정답 형식이 필요하다. 이 예제의 존재는 밈 콘텐츠 생성 성능의 증거가 아니다.

**Qwen2.5-Omni:** [ms-swift 등록 코드](https://swift.readthedocs.io/en/v4.2/BestPractices/MLLM-Registration.html)는 Thinker의 언어 모델·시각/음성 타워·aligner를 나누고 Talker/Token2Wav를 고정한다. [공식 프레임워크 FAQ](https://swift.readthedocs.io/en/v4.1/Instruction/Frequently-asked-questions.html#q42-training-specific-models)에서도 Thinker만 훈련한다고 명시한다. 따라서 '음성까지 포함한 밈 정보를 입력하여 콘텐츠 내용을 학습했다'는 실험과 '밈의 발성·목소리 생성기를 학습했다'는 실험은 별개다.

**Qwen3-Omni:** 한국어 음성 입출력과 Instruct/Thinking 구성 차이, 추론 GPU 표를 읽었다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Instruct)는 Instruct를 텍스트+음성 출력 모델로 명시한다. 프레임워크의 모델 지원 목록은 읽었지만 해당 모델의 전 부품을 훈련하는 코드와 사용자의 작업에 맞는 메모리 예산은 이번 검토에서 확정하지 못했다. 기술 보고서 전문을 읽었다고 주장하지 않는다.

Hugging Face 저장소의 노트북 목록에는 RAG·무료 T4 등의 예제가 있지만 이번에 열린 `.ipynb` 페이지는 목록/파일 소개 수준이었다. 그 표제를 전 모달리티 콘텐츠 제작 실험의 실행 근거로 쓰지 않는다. 상세 판단에는 본문을 읽은 위 `.py` 예제만 사용했다.

## 같은 기본 모델 비교에서 유지할 범위

아래는 문헌의 실험 결과가 아닌 **본 연구를 위한 설계 제안**이다.

1. 각 후보를 시험한다면 모델군별로 동일한 체크포인트 revision을 고정한다. RAG 조건은 그 가중치를 유지하며 시점별 근거 저장소만 갱신한다. 파인튜닝 조건은 같은 시작 가중치에서 동일 시점의 허용 자료로 adapter/가중치를 갱신한다. 서로 다른 모델을 사용해 생긴 차이를 갱신 방법의 효과로 주장하지 않는다.
2. 원본 이미지·오디오·영상 데이터와 OCR·전사·설명문을 별도 입력 유형으로 기록한다. 전사본만 읽은 실험은 음향·억양·시각 밈을 직접 처리한 실험이 아니다. 원본 다중모달 처리와 텍스트 변환 처리는 보조 비교로 분리할 수 있다.
3. LoRA 대상 언어 모듈, 시각/음성 인코더, aligner, 음성 출력 부품 중 어떤 것이 업데이트되는지 저장한다. 고정된 Talker가 말을 출력해도 Talker를 학습했다고 쓰지 않는다.
4. 시간 T의 두 조건에는 T까지 허용된 자료와 설명 버전만 제공한다. 모델 자체의 사전학습 지식은 남으므로 모델 카드의 학습 시점 주장만으로 밈을 전혀 몰랐다고 가정하지 않는다. 사전 노출 가능성을 별도로 다룬다.

최종 제작물이 이미지나 영상이라면, 위 세 모델만으로 픽셀/프레임 생성 능력을 비교하는 설계는 성립하지 않는다. 가능한 선택지는 **(가) 해당 매체의 생성기를 비교 대상 모델에 포함**하거나, **(나) 양쪽이 같은 고정 렌더러·음성합성기·편집기를 사용하게 하여 밈 선택·구성·문구·타이밍 계획의 적응 효과를 평가**하는 것이다. (나)의 제작물도 평가할 수 있지만, 결론은 그 조합의 효과이며 이미지/영상 생성기 자체를 밈으로 학습시킨 효과가 아니다. 출력 매체가 정해지기 전에 연구를 텍스트 출력으로 확정하지 않는다.

| 제작물: 글·이미지·음성·숏폼 영상 중 무엇인가 | 직접 생성 가능한 모델과 고정 제작기 사용 여부, 훈련 목표를 결정한다. |
| 실제 자료 구성: 이미지 해상도, 영상·음성 길이와 수, 언어, 음성/영상 원본 보유 여부 | 프레임·오디오 입력 토큰과 메모리, 개인정보/권리 처리 및 입력 품질을 결정한다. |
| 밈별 설명·용례·제작 지시·바람직한 제작물/선호 평가의 존재 | RAG용 근거와 SFT/선호학습용 supervision을 어느 비용으로 준비할지 결정한다. 단순 수집 목록은 곧바로 제작물 정답 데이터가 되지 않는다. |
| GPU 접근과 금액·실행 시간 상한 | 후보 및 정밀도, LoRA 범위, 업데이트 수와 반복 수를 결정한다. |
| 시점별 업데이트 횟수와 비교 조건 | 갱신 시간, 재학습·검색 인덱스 비용, 평가 호출량을 결정한다. |

현재 실제 GPU 시간·파인튜닝 메모리·밈 생성 성능은 미측정이므로 금액을 만들지 않는다. 이후 확인된 GPU 시간당 요금에 **실측 훈련/추론 시간 × GPU 수**를 적용하고 저장·검색·전처리·평가 비용을 따로 기록한다. 공개 가중치라고 전체 실험 비용을 0원으로 잡지 않는다. 이번 문헌 검토에서 모델/API/훈련 호출은 0회이며 유료 자원은 사용하지 않았다.

## 확인 기록

본문을 읽은 1차 출처: Google Gemma3n 개요·E2B/E4B 카드·Gemma 이용 조건, Qwen2.5/3-Omni 공식 README와 가중치 카드·3B 라이선스, Hugging Face Gemma recipes의 영상+음성 `.py` 구현, ms-swift 모델 등록·FAQ·Megatron 멀티모달 문서. 구체 수치·기능은 해당 절 근처에 직접 링크했다. 검색에서 나온 제3자 요약·커뮤니티 경험담은 이 표의 근거로 사용하지 않았다.

로컬에서는 기존 `Saanvi-C1-3B` 캐시의 `config.json`만 읽었다. `StableLmForCausalLM`, `model_type=stablelm`, 최대 위치 4096, BF16 설정이며 다중모달 인코더가 명시된 설정은 아니다. 이 텍스트 모델의 프롬프트 준비 기능이 곧 위 다중모달 비교 실험의 구현이라는 뜻은 아니다. 기존 코드·원자료·실험 기록을 변경하지 않았다.
