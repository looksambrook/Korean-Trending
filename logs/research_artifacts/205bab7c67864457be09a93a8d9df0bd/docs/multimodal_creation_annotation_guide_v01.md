# 멀티모달 밈 제작 비교: 독립 주석·평가 지침 초안

작성일: 2026-09-15. 작성 주체: AI. 상태: **개발 파일럿용 제안**. 실제 평가자 수·보상·모집·척도는 미확정이며 이 문서를 작성한 것을 사람 평가로 집계하지 않는다. 사용자에게 확인받지 않은 표본 수나 KCI 공식 조건을 설정하지 않는다. 연구 설계의 상위 기준은 [프로토콜](multimodal_creation_protocol_v01.md)이다.

## 1. 평가할 것

수집된 밈을 이용한 새로운 콘텐츠가 요청의 목적에 맞는지, 해당 밈의 필요한 특징을 보존하는지, 시점과 사용 맥락에 적절한지 평가한다. 설명을 잘 쓰는 것과 콘텐츠를 잘 만드는 것은 구별한다. 완성된 영상이 필요한 요청에서 대본만 나온 경우 제작 실패로 남긴다.

창작 과제에는 하나의 모범 작품만 정답으로 두지 않는다. **필수 보존 요소, 허용 가능한 변형, 맥락상 부적절한 적용, 판정 불가능한 부분**을 먼저 기록한다. AI가 작성한 지침·예시는 평가 설계 초안이며 독립적인 실제 밈 정답이 아니다.

## 2. 근거 주석: 생성 결과를 보기 전에 작성

독립 주석자는 시점 제한된 동일 자료 묶음만 보고 아래 항목을 작성한다. 제작 모델의 출력, 조건명, 검색 결과 순위, 개발 성능표는 보지 않는다. 실제로 읽거나 재생하지 못한 자산은 미확인으로 남긴다.

| 항목 | 기록 내용 |
|---|---|
| 식별·시점 | 계열 ID, 기준 시각, 원자료·지식의 버전과 해시, 실제 주석 작성 시각 |
| 용례·맥락 | 자료에서 확인한 사용 상황과 의미. 게시자의 설명과 주석자의 해석을 구별 |
| 필수 특징 | 핵심 문구·인물 관계·화면 배치·표정·말투·리듬·동작·타이밍 중 해당 계열에 필요한 것 |
| 변형 허용 | 바꿀 수 있는 소재·표현·매체, 변형해도 유지해야 할 관계. 치환 슬롯은 필요한 계열에만 정의 |
| 근거 위치 | 자산 ID와 텍스트 구간, 이미지 영역, 오디오·영상 시각 등 실제 확인 위치 |
| 사용 판단 | 적절한 맥락, 부적절한 맥락, 판단 불가. 최신 여부만으로 좋고 나쁨을 정하지 않음 |
| 불확실성 | 상충하는 용례, 미확인 출처, 누락된 소리·화면, 필요한 추가 근거 |
| 작성·검수 | 작성자와 검수자의 역할, 자동 제안 여부, 수정 전후 버전, 실제 작업 시간 |

사후에 주석을 만들 수는 있지만 작성 시각을 과거로 바꾸지 않는다. 그 주석과 평가 결과는 평가 전용으로 보관하고 과거 RAG 인덱스·FT 학습 자료·프롬프트에 넣지 않는다. 자동 주석을 사람이 승인한 경우에는 `AI 제안 + 사람 검수`로 남기며 처음부터 사람이 독립 작성한 정답과 구별한다.

## 3. 제작 결과 평가의 순서

1. **출력 상태 확인:** 계획한 모든 요청×시점×조건×반복을 유지한다. 생성 없음, 정책상 거절, 형식 오류, 재생 불가, 일부 매체 누락을 먼저 구별한다. 존재하지 않는 완성물을 점수로 평가하지 않는다.
2. **요청과 완성물만 평가:** 동일한 제작 요청과 익명화된 실제 완성물을 보고 요청 적합성·자연스러움·완성도를 평가한다. 필요한 소리·영상을 실제 재생할 수 있어야 한다.
3. **동일 기준 자료로 특징·시점 평가:** 모든 조건에 동일한 시점의 근거와 보존 기준을 보여주고 밈 활용·시점 적합성을 평가한다. 조건별 검색 자료를 그대로 평가자 참고자료로 주지 않는다.
4. **불일치 확인:** 원점수는 보존한다. 검수자가 다시 판단하면 별도 버전과 이유·시간을 남긴다. 서로 다른 해석이 모두 가능한 경우 억지로 하나의 점수로 합의시키지 않는다.

조건명과 모델·체크포인트·검색 여부는 평가 화면과 파일명에서 숨긴다. 실제 작품의 문체로 조건을 추측하는 것까지 완전히 차단했다고 주장하지 않는다. 제시 순서와 평가자 배정은 개발 파일럿 뒤 잠그며, 같은 평가자가 다른 조건을 보는 효과와 사전 밈 친숙도도 기록한다.

## 4. 점수의 기준 제안

아래 1–5 척도는 개발 파일럿에서 이해 가능성과 일관성을 확인할 **초안**이다. 2와 4는 인접 기준 사이이며 구체적 근거를 남긴다. `해당 없음`, `자료 부족`, `재생 실패`는 0점이나 중간 점수로 바꾸지 않는다. 척도가 잠기기 전에는 본실험을 시작하지 않는다.

| 평가 차원 | 1의 예 | 3의 예 | 5의 예 |
|---|---|---|---|
| 밈 특징 보존 | 필요한 핵심 특징이 없어 다른 표현처럼 보임 | 일부 특징은 유지하지만 중요한 관계·억양·타이밍 등이 어긋남 | 해당 용법에 필요한 특징을 유지하면서 요청에 맞게 변형함 |
| 요청·맥락 적합성 | 목적·독자·상황과 분명히 맞지 않음 | 목적을 일부 충족하지만 사용하기에 중요한 수정이 필요함 | 목적과 제약에 맞고 사용 맥락이 자연스러움 |
| 완성물 품질 | 읽기·보기·듣기 어렵거나 주요 내용 전달이 깨짐 | 내용은 이해되지만 문장·배치·음향·장면 연결에 눈에 띄는 문제가 있음 | 선택한 매체에서 내용 전달과 표현이 명료하고 일관됨 |
| 시점 적합성 | 요청 시점에서 확인된 의미·용법과 충돌함 | 일부 맥락은 맞지만 시점상 중요한 차이를 놓침 | 최신·회고 등 요청의 시간 맥락에 맞는 용법을 사용함 |

해로운 적용·오해를 일으키는 사용은 점수와 별도로 오류 유형과 근거를 남긴다. 오래된 밈이라는 이유만으로 해로운 적용으로 분류하지 않는다. 근거가 불명확할 때 적절히 보류하거나 중립 대안을 제시한 결과와 단순 생성 실패를 구별한다. 재미·선호는 친숙도와 취향의 영향을 별도로 살펴볼 선택 지표이며 정확한 밈 활용과 동일하게 취급하지 않는다.

## 5. 통제 항목과 전체 분모

평가 묶음에는 새로운 계열·새 변형, 사용 맥락이 바뀐 계열, 여전히 적절한 이전 용법을 포함할 수 있다. 밈 활용이 어울리지 않는 요청과 밈 여부·해석 근거가 부족한 자료도 별도 통제로 준비한다. 실제 사례가 없으면 연구자가 작성한 예시나 AI 합성 예시로 분명히 표시하며 자연 발생 사례처럼 보고하지 않는다.

원본·재게시·번역·크롭·프레임·음원 등 연결된 자료는 독립 표본으로 부풀리지 않는다. 같은 작품의 여러 평가와 같은 계열의 여러 요청도 서로 다른 독립 밈처럼 세지 않는다. 출력 성공 사례의 품질만 보고하지 않고 계획된 전체 항목의 제작 실패·지원 불가·평가 결측을 함께 보고한다.

## 6. 보관할 최소 평가 기록

`study_id`, 익명 `display_id`, 평가자 ID, 척도 버전, 실제 평가 시각, 평가 단계, 점수별 판정 상태·근거 위치, 오류 유형, 사전 친숙도, 사용한 기준 자료 해시, 작업 시간, 원점수/검수 버전을 남긴다. 조건·실행 ID와의 연결 표는 분석용 별도 파일로 둔다.

사람 평가는 실제 사람이 수행한 경우에만 `human_rating`으로 기록한다. 화면 테스트나 AI가 채운 점수는 별도 preview 자료다. 자동 파일 검사 결과는 기술적 제작 상태이며 사람이 판단한 의미·적합성 점수가 아니다. 아직 이 지침에 따른 실제 사람 주석·평가 자료는 없다.

## 7. 공통 제작 프롬프트

[공통 시스템 프롬프트](../prompts/multimodal_creator_system_v01.txt)를 준비했다. C0·CR·CF는 같은 제작 지시와 요청 형식을 사용한다. CR의 검색 자료는 별도 입력 영역으로 제공하며 CF에는 허용 자료로 실제 학습한 체크포인트를 사용해야 한다. 프롬프트가 파인튜닝을 대신하지 않는다.

매체별 입력 포장, RAG 검색 규칙, 학습 목표 포맷, 제작 도구, 출력 계약은 모델과 최종 제작물 형식이 정해진 뒤 구현한다. 이 프롬프트는 아직 모델에 실행하지 않았으며 검증된 최종 프롬프트라고 표시하지 않는다. 평가용 정답·점수 기준을 제작 프롬프트에 자동 삽입하지 않는다.
